**Shared xcodebuild lock.** Every phase-local `xb2.sh` invocation, including builds, follows these steps:
1. Wait until `mkdir "$LOCK"` succeeds.
2. The wrapper serializes invocations using the phase-local lock; it does not use a global `pgrep` gate.
3. Run exactly one `xcodebuild` with an explicit Xcode 26.6 developer directory, destination and derived-data path.
4. `rmdir "$LOCK"` when it exits, also when it fails.

Unrelated jobs may run concurrently when they use a different derived-data path and an explicitly different device destination. Generic simulator destinations do not reserve a global simulator device. Never kill an `xcodebuild`, a test runner or `testmanagerd` mid-launch. Output is buffered until exit, so a quiet log is not a hang.
