<objective>
Land the structured-error foundation for QUAL-04 additively in AppModels, holding the existing `AppError` enum at byte-stable parity (D-05). Create the type-erasing `AnyHashableBox`, the `Context`/`ContextKey` typed-context vocabulary, and the `ErrorInfo` surfaced-error payload (D-06); add the per-kind localized `solution` and `LocalizedError` conformance (D-07). Seed the Wave-0 tests (all-cases parity table, solution/LocalizedError round-trip, box ergonomics) that VALIDATION.md requires.

Design decision (resolves RESEARCH Assumption A1 — the context storage mechanism): `AppError` stays the unchanged 12-case value enum. A Swift value enum cannot store per-incident data without an associated value or a struct conversion, and either would break the 12 cases plus the ~7 `switch error` / `if case .x = error` pattern-match sites across DownloadClient, SettingFeature, ReadingFeature, AppComponents, AppModels — the exact behavior/appearance parity this milestone locks (RESEARCH Common Pitfalls, Pitfall 1). So per-incident `context` is carried on the companion `ErrorInfo` struct (assembled at the owning reducer — the nearest surface, D-12), `solution` is a computed property on the enum, and the presentation surfaces (toast, `.errorInfo` destination, `ErrorInfoView`) carry `ErrorInfo`. This fully delivers D-06's typed `Context?` while keeping the enum parity-safe.

Purpose: every downstream plan (failure surface, routing, the `try?` sweep) depends on these types existing.
Output: `AppError+Context.swift` (new), `AppError.swift` (additive extensions), new AppModels `.xcstrings` solution keys, two new `AppModelsTests` files.
</objective>
