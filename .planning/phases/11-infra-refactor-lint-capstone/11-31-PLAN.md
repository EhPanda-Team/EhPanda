<objective>
Close G-11-8 (cosmetic): the page-count symbol in the gallery cells renders visibly larger than it
did before the Phase 11 UI sweep.

Commit `6dd51b00` rewrote six inline `HStack { Image(systemSymbol:); Text(...) }` groups into
`Label`s, driven by the `label_text_image_shorthand` rule. The ambient font is unchanged
(`.footnote` before and after) and neither version ever sized the icon explicitly, which isolates
the cause: a bare `Image` renders an SF Symbol at the ambient font's default symbol scale, whereas
a `Label` icon under the default `titleAndIcon` style is sized from the label's own font and line
metrics — a larger glyph at an identical font. The project's `Label(_:systemSymbol:)` shims are
ruled out; both compose `Text` and `Image` verbatim with no sizing.

The fix reasserts an explicit relative icon scale at the six affected sites. It does not revert to
a hand-composed stack — that would reintroduce a lint error at `error` severity, and suppression is
forbidden by project policy.

Purpose: restore the pre-sweep appearance without giving up the lint bar the sweep earned.
Output: six corrected call sites across three files, one settled scale value, appearance parity.
</objective>

## Diagnosis status

G-11-8 is **already diagnosed** (`11-UAT.md` §Gaps, and
`.planning/debug/g-11-8-page-count-symbol-size.md`). Do not re-investigate. Established and cleared:

- The symbol shims are not the cause; no font was moved or dropped; no ambient label style sits
  above the cells. The introducing commit is `6dd51b00` and its blast radius is that commit alone.
- Six sites share the mechanism. **Not affected, already checked and cleared — do not touch:**
  `DetailView+HeaderSection`, `DetailView+Subviews`, `ToolbarItems`, `CommentsView`,
  `FolderManagerView`, `QuickSearchView`. Every one of those carries an icon-only label style with
  an explicit font, which already pins its icon size. The regression class is confined to inline
  `titleAndIcon` labels that replaced an icon-plus-text stack.

One sub-decision is genuinely open and is settled by the visual A/B in Task 1's `<verify>`, not by
guessing: which relative scale value restores parity. Repo precedent is the smaller value; the
larger value is theoretical parity with a bare `Image`.
