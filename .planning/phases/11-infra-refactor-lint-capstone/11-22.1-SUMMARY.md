# Phase 11 Plan 22.1: Remaining @MainActor Sweep + Full-Suite Parallel Gate Summary

The D-13 sweep is complete across all 50 originally-annotated test files, and the phase's first
full-suite parallel gate passed **three consecutive times with zero issues and no retries**.

Two commits: `ea9a71f6` (the sweep) and `320d942d` (a hole in the gate itself).

The headline finding is not in the sweep. **The gate this plan exists to run was skipping three
test targets**, two of which hold this phase's own isolation work. That is written up first.

## The gate was not gating what it claimed

The plan's verification command is `xcodebuild test -scheme EhPanda`. That scheme drives
`AppPackage/Tests/FeatureTests.xctestplan`, which listed 15 of the package's 18 test targets.
Missing:

| Target | Why it matters here |
|---|---|
| `ImageClientTests` | **11-20 removed its serialization trait.** The gate could not have caught a parallel regression in it. |
| `CookieClientTests` | Holds `DidLoginKeyTests` and the production `DidLoginKey.subscribe` race **11-20 root-caused and fixed**. |
| `ReadingFeatureTests` | Three of the files swept by this plan. |

This was an omission, not a decision: every other target was appended to the plan in the commit
that created it (`e13bf952`, `571d126b`, `5be4a662`, …), and these three never were. It also means
`xcodebuild build-for-testing -scheme EhPanda` — the phase's standing lint gate for `Tests/` — was
not compiling or linting those targets either. The first build cycle of this sweep reported a clean
`EhPanda`-scheme build while `ReadingFeatureTests` and `ImageClientTests` were in fact broken; only
switching to `AppPackage-Package` surfaced it.

Adding the three targets took the gate from **523 to 565 tests**. Every run reported below is on
the repaired plan.

## The sweep

23 files across 6 targets, not the plan's 18 across 5 — `HomeFeatureTests` was missing from the
enumeration entirely, and `SettingFeatureTests`, `AppFeatureTests`, `DetailFeatureTests` and
`ReadingFeatureTests` each had one more annotated file than counted.

Method followed 11-22 exactly: strip all 34 annotations, restore to a compiler fixpoint. That took
**12 build cycles** — the "one failing file per build" trap 11-22 documented held throughout, and
each restore surfaced the next file rather than the whole set.

One addition to the method. 11-22's flagged item 4 warned that a build-only workflow proves the
absence of *under*-annotation but not of *over*-annotation, and that its regex produced one false
positive. So after the fixpoint, a probe listed every annotated member whose body named no known
main-actor API (22 of them), all 22 were stripped at once, and the build was rerun. **The compiler
demanded 20 back** — they call a `makeStore()` helper that is itself `@MainActor`, which the probe
cannot see through. The 2 it did not demand were `ImageClientTests`' — matched on `dataCache.store(`,
precisely the false-positive shape 11-22 hit. Every survivor in this plan is therefore either a
direct reference to a known main-actor type, or was individually proven necessary by removal.

### The metric that actually moved

As in 11-22, annotation count is the wrong yardstick — it conflates scope with reach, and it rose
here for the same reason. What matters is how many `@Test` cases are pinned to the main actor:

| | `@Test` cases | main-actor-isolated | free to run off the main actor |
|---|---|---|---|
| Before | 82 | 82 | 0 |
| After | 82 | **72** | **10** |

**10 cases freed**, 9 of them the whole of `ImageClientTests`. The other 72 construct a `TestStore`,
or drive `PageHandler` / `GestureHandler`, and cannot leave the main actor without a change to TCA
or to those types. Case count is unchanged at 82 — nothing was lost or skipped.

### ImageClientTests: the plan's prediction was wrong, and that is the useful part

The plan flagged UIKit image rendering as "a likely genuine keeper — UIKit image drawing is
main-actor-adjacent". It is not. `UIGraphicsImageRendererFormat`, `UIGraphicsImageRenderer` and
`UIImage.pngData()` are all callable from a nonisolated context, so `makePNGData` and all nine
cases compile and pass with no annotation at all. 11-22 hit exactly this in
`DownloadProcessCacheTests` and recorded the same surprise. **Two independent expectations, both
wrong, in the same direction** — worth treating "UIKit means main actor" as a disproven prior for
the rest of the phase rather than re-testing it a third time.

## Deviations from Plan

**1. [Rule 2 — Missing critical functionality] The scheme's test plan omitted 3 test targets**

- **Found during:** Task 1, first build cycle. The `EhPanda` scheme reported a clean
  `build-for-testing` while `ReadingFeatureTests` and `ImageClientTests` were in fact broken.
- **Issue:** `FeatureTests.xctestplan` listed 15 of 18 targets. `CookieClientTests`,
  `ImageClientTests` and `ReadingFeatureTests` were never added when created.
- **Fix:** all three appended to the test plan. Gate coverage 523 → 565 tests.
- **Why fixed rather than flagged:** this plan's success criterion is that *the full suite* passes
  in parallel. A gate that skips the target 11-20 de-serialized and the target holding 11-20's
  production race fix cannot establish that.
- **Files modified:** `AppPackage/Tests/FeatureTests.xctestplan`
- **Commit:** `320d942d`

**2. [Scope] 23 files across 6 targets, not 18 across 5**

The plan's enumeration omits `HomeFeatureTests` entirely (2 files) and undercounts
`SettingFeatureTests` (10, not 9), `ReadingFeatureTests` (3, not 3 — correct),
`AppFeatureTests` (3, not 2) and `DetailFeatureTests` (3, not 2). All 23 were swept.

**3. [Scope] Justification comments are per-suite, not per-annotation**

Same reasoning 11-22 recorded and the same shape: one comment above each retaining type naming the
requirement and stating that unannotated cases are deliberately free. 81 near-identical copies
would bury the two that say something specific (`PageHandler`, `GestureHandler`).

**4. [Scope] `AppPackage-Package` was used for the build fixpoint**

The plan's Task 1 verification command is `build-for-testing -scheme EhPanda`. Because of
Deviation 1 that command could not compile two of the swept targets, so the fixpoint loop ran
against `AppPackage-Package`. The plan's command was re-run and is green on the repaired plan.

## Flagged for owner review

**1. Criterion 4 is met, but D-13's yield is 17 cases phase-wide and no measurable time.** 157 of
186 cases remain main-actor-isolated because TCA's `TestStore.init` and `.state` are. 11-22 raised
this; this plan confirms it holds across all six remaining targets — the ceiling is uniform, not a
Downloads peculiarity. If the phase wants wall-clock from test parallelism, the lever is TCA's
testing API or splitting reducer tests from IO tests, not further `@MainActor` hygiene. There is
nothing left to sweep.

**2. Nothing re-audits the test plan.** The gap this plan fixed went unnoticed across at least
three target additions and every prior plan in this phase, because nothing compares
`AppPackage/Tests/*` against `FeatureTests.xctestplan`. A one-line check would close it
permanently; a good home is 11-29's capstone or the commit gate. Until then the same silent drift
can recur the next time a target is added.

**3. `build-for-testing -scheme EhPanda` is the phase's standing lint gate for `Tests/`, and it
inherits the same coverage.** It was not linting `CookieClientTests`, `ImageClientTests` or
`ReadingFeatureTests`. Those three are now covered and clean, but any lint conclusion drawn about
`Tests/` earlier in this phase — including 11-19's and 11-20's, which touched two of them — was
drawn from an incomplete gate. Nothing is currently violating; the exposure is retrospective only.

**4. "UIKit implies main actor" is now disproven twice.** 11-22 expected a restore for
`UIGraphicsImageRenderer` in `DownloadProcessCacheTests` and did not get one; this plan expected
the same for `makePNGData` and did not get one. Worth recording in 11-EXCEPTIONS.md so the next
sweep does not spend a build cycle on it.

**5. `GestureHandler` and `PageHandler` are `@MainActor` types with no UI in their test path.**
Both are pure coordinate/page arithmetic, and both pin every case that touches them to the main
actor. Neither obviously needs the isolation — it looks inherited rather than required. Removing
`@MainActor` from those two production types would free 15 more cases, but it is a production
change well outside this plan's test-only scope.
