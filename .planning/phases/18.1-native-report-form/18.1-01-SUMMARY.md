# Phase 18.1 Plan 01: Report form parser, per-type report URL and the two requests Summary

**EhPanda can now read the site's report form from a gallery's `?report=<type>` page and post a report exactly as the
site's own form does: one attempt, to a URL rebuilt from the validated gallery URL, never the page's `action`. A reply
counts as sent only when it no longer shows the form and is not one of the site's error pages. Nothing here is visible
yet; 18.1-03 wires it into the reducer.**

## Accomplishments

- **Fixtures, models and parser (Task 1, `868a5dc54`):**
  - The three saved report pages (guest, 2026-11-06) are test fixtures `ReportSelect`, `ReportChild` and
    `ReportOther`, byte-identical to the phase `fixtures/` copies. The DMCA and technical pages stay in `fixtures/`
    only (D-06).
  - `ReportType` has exactly `child` and `other`, in the C-13 order. There is no case or table for `dmca`, `excupd`
    or `revert`.
  - `parseReportForm` returns the recognised types, the trimmed `#r_email` value and `hasDetails`. It ignores
    unknown option values and throws when the form, picker, email, details or submit is missing, so the step-one
    page (`ReportSelect`) throws.
  - `parseReportSubmission` returns `.sent` only when the reply has no `#reportform`.
- **Report URL and requests (Task 2, `16cd70137`):**
  - `CommentReportTarget.reportURL(for:type:)` gives `https://<host>/g/<gid>/<token>/?report=<type>` with exactly
    one query item. Every look-alike host, port, credential and non-gallery case that `reportURL(for:)` rejects
    returns nil for both types.
  - `ReportFormRequest` GETs the page and parses it; a non-2xx status or a page that is not a form throws.
  - `SendReportRequest` posts `report_type`, `r_email`, `r_details` and `sendreport=Send Report`, URL-encoded, with
    `attempts: 1`. A transport error or a 503 throws after exactly one attempt. A 2xx reply that is a site error
    page throws; otherwise it is classified by `parseReportSubmission`.
  - Threat review: neither request reads a form `action` (T-18.1-01), the POST is never retried (T-18.1-02), and
    neither file logs anything, so the email and details are never logged (T-18.1-03). No package was installed
    (T-18.1-SC).
