<domain>
## Phase Boundary

Phase 18 shipped "Report on {site}" as an alert followed by the site's own report page in an in-app web sheet. This
phase replaces that first route with EhPanda's own native form, inside the app, posting the site's own report fields
(owner msg 1931). The site's report page stays, as the fallback for every case the form cannot handle.

Delivered:

- A native "Report on {site}" sheet opened directly from a comment's Report action (comments list and Detail strip;
  all three entry points of UI-SPEC C-4). The old confirmation alert is removed.
- The form reads the site's report form for the gallery first; if it cannot be read, the sheet says so and offers
  the site's page.
- From a comment: two reasons (child pornography, other illegal content), email, details prefilled with the comment,
  and Send Report. The request goes to the site exactly as the site's own form would send it.
- The states of UI-SPEC C-13: loading, ready, sending, sent, failed and unavailable.
- Tests: parser, request, reducer and string tests in FeatureTests; a UI test for each C-13 state on iPhone and iPad;
  a live check on the real site with Proxyman blocking the outgoing report (owner msg 1933).

**Not in this phase:**

- Any gallery-level Report, now or later, unless distribution is blocked without it (owner msg 1975, D-06). There is
  no gallery origin, no copyright route, no technical reasons and no reason table kept for later. Frame 32 is
  withdrawn.
- The published contact link (Phase 20, unchanged from Phase 18 D-11).
- Phase 19's snapshots of frames 25 to 34. Phase 19 must cover them, as it covers frames 01 to 24.

<decisions>
## Implementation Decisions

### Route

- **D-01:** **EhPanda's own form is the first route; the site's page is the fallback** (owner msg 1931). Report on a
  comment opens the native sheet directly, with no alert. `comment.report.confirm_title` and
  `comment.report.confirm_body` are retired with the alert (UI-SPEC Copywriting, C-4). The existing `ReportPageSheet`
  (Phase 18 18-11: `SessionWebView`, `SheetCloseToolbar`, the app's cookies for the report host only) is kept and
  opens from the form's "Open Report Page" button (unavailable, failed).
- **D-02:** **Reporting still goes to E-Hentai or ExHentai only** (Phase 18 D-10 carried). The form posts to the
  gallery's own site. Nothing is sent to EhPanda, and EhPanda keeps no copy of the report or the email (Pluso msg
  1934 lead default; `report.intro`).
- **D-03:** **No copyright route** (owner msg 1975). The site's DMCA form is a sworn legal statement with about a
  dozen fields (Pluso msg 1934). EhPanda offers no copyright reason and no copyright layout; a copyright holder uses
  the site. The earlier "Copyright picked" design (frame 32) is withdrawn (Colo msg 1978).

### Reasons

- **D-04:** **From a comment, only the two illegal-content reasons are offered** (owner msg 1950, "Illegal content
  only"): `report.reason.child`, then `report.reason.illegal`, with the misuse warning. There is no spam reason:
  spam is handled by Block. Copyright and the two technical reasons are not offered anywhere (owner msg 1975).
- **D-05:** Two site type values are used: child → `child`, illegal → `other` (form facts; saved pages in
  `fixtures/`). The site's other values (`dmca`, `excupd`, `revert`) are ignored by the parser and have no model case.
  The labels are EhPanda's own copy (Camo's file), never the site's English names.
- **D-06:** **No gallery reports, now or later, unless distribution is blocked without them** (owner msg 1975, Ato
  card 1972). Comment report exists purely for Apple's guidelines, and the owner does not want galleries reported.
  So there is no gallery entry point, no gallery origin in the model, reducer or view, no DEBUG key to reach one, and
  no gallery reason table built for future use: the comment set (child, illegal) is the only one. This replaces the
  earlier note that a gallery entry was a future decision (msgs 1956, 1959).

### Form content

- **D-07:** **A comment report prefills Details** (Pluso msg 1934 lead default), because the site's report covers
  the whole gallery and moderators need to know which comment. The prefill is English in every app language (the
  site's staff work in English; Camo msg 1938), exactly:

  ```
  Reporting a comment by {name} ({date}):
  "{comment text}"

  ```

  The cursor goes after the blank line. Send Report stays dimmed until Details has text beyond the prefill.
- **D-08:** **Email is required, as on the site, and never stored** (Pluso msg 1934; `report.email.footer`).
  It is checked on Send only. If the loaded form carries a remembered address (signed-in accounts), it is prefilled;
  EhPanda does not keep it.

### Copy and design

- **D-09:** **All new strings come verbatim from the owner-approved report copy** (Phase 18 D-15 carried). The owner
  approved Camo's copy (the msg 1960 text) in owner msg 1975. Camo's final file (msg 1977, headed "APPROVED msg
  1975") is committed byte for byte as [18.1-COPY-REPORT-FORM.md](18.1-COPY-REPORT-FORM.md) and is not edited in
  execution. Every key is filled for all six locales (Phase 18 D-22).
  - 23 keys ship. The six rows struck out as DROPPED exist only for out-of-scope gallery reasons and are left out
    of every catalog: `report.reason.updates`, `report.reason.restore`, `report.reason.copyright`,
    `report.help.updates`, `report.help.restore` and `report.help.copyright` (owner msg 1975).
  - The sheet's top-left button is the system `Button(role: .close)`, icon only, with no string of ours (Colo msg
    1974; a note fix, not a string change). The existing `cancel` is the third button of the failed alert (Retry /
    Open Report Page / Cancel).
  - `report.reason.choose` ("Choose a Reason") is approved and lands with the rest, but C-13 has no picker that shows
    it. It is flagged to the lead (Camo/Colo) rather than dropped by the planner.
  - **Dropped in 18.1-02 (lead decision, msgs 1980/1983):** `report.reason.choose` does not ship, because the final
    C-13 reason list is a plain checkmark list with no picker, so the string is never shown. 22 keys ship, and
    `18.1-copy-check.py` treats `report.reason.choose` as must-be-absent next to the six rows above. The approved
    copy file is unchanged.
- **D-10:** **The design contract is UI-SPEC C-13** in the Phase 18 spec, final as of Colo msg 1978 (see "Spec and
  mockups" below). Layout calls are the designer's and are not changed in execution (Phase 18 D-17, D-17a). Where a
  frame and the text differ, the text wins. Its rulings include:
  - The sheet's one action is in `.safeAreaBar(edge: .bottom)`, built like the first-launch Continue (C-1). It is a
    full-width `.glassProminent` large button (owner msg 1955; Colo msgs 1958, 1963).
  - The bar has no background, material, fill or divider; the form's scroll view sets
    `.scrollEdgeEffectStyle(.soft, for: .bottom)` (owner msg 1965; Colo msg 1966). The shipped
    `FirstLaunchGateView` already follows this.
  - The label follows the state: `report.send`, then a spinner with `report.sending`, then `report.sent.done`. It is
    `comment.report.open` for the unavailable state; under the failed alert it stays Send Report.
  - The top bar holds the system Close (`Button(role: .close)`, icon only; Colo msg 1974).
  - The top bar holds only Close: no trailing toolbar button. ⌘↩ triggers the pinned button when it is enabled.
  - The unavailable `ContentUnavailableView` has no actions of its own.
- **D-11:** **No analytics.** Moderation sends no analytics signal (the 18-11 prohibition), and the form adds none.
- **D-12:** **Every build, no flag** (Phase 18 D-16 carried).

### Testing

- **D-13:** **Live test on the real site with Proxyman blocking the report** (owner msg 1933). The live test runs
  against a real spam comment, with Proxyman blocking the outgoing report request. The request is captured and
  checked, and no real report reaches the site. The saved copies of the site's pages back the automated tests.
  **Changed by the owner (msgs 1981, 1995, 1997, 1999), before the check ran:** the comment is a real one that fits
  "Other illegal content" (doxxing, a threat or an illegal sales link), never spam; Proxyman blocks every request
  from the app plus e-hentai.org, exhentai.org and their subdomains for every method; the pages the app needs are
  saved beforehand with a guest shell GET and served by Map Local; ordinary requests and Mac probes are seen blocked
  first; and Send must produce exactly one blocked POST to the gallery's `?report=other` URL. 18.1-05 Task 2 has the
  steps.
  **Owner msg 2066:** the Block List blocks the CONNECT tunnel before Map Local can answer, so Proxyman instead answers
  every request from the app locally (the saved pages, and a local 403 for everything else, the report POST included);
  nothing is forwarded. The test comment is the uploader's paid-uncensoring sales link on gallery 4308676.
- **D-14:** **The live check is the phase's only checkpoint, and an agent runs it** (owner rule msg 1652, as for 18-12
  Task 3). It is a `gate="blocking-human"` checkpoint in 18.1-05: auto mode does not approve it on anyone's behalf.
  Execution pauses there, and an agent runs the check and records the result. Every other task is `type="auto"`:
  with the copy approved (owner msg 1975), plans 18.1-01 to 18.1-04 and the 18.1-05 gate run straight through.
- **D-15:** FeatureTests and UI tests cover every C-13 state. The UI tests run on `$PHONE` and `$PAD`, with stubbed
  responses only. No UI test reaches the live site.

### Developer defaults (changeable)

- **DD-01:** The form loads the site's `?report=other` page. It carries the type picker and the email and details
  fields, and a remembered email if there is one. `child` and `other` share those fields, so one load covers both
  reasons. The sheet is "unavailable" if the page lacks `#reportform`, a `select#report_type` offering both `child`
  and `other`, `#r_email`, `#r_details` or the `sendreport` submit.
- **DD-02:** The POST URL is rebuilt from the gallery URL (`CommentReportTarget`, `report=<type>`), never taken from
  the page's `action` attribute. The body holds the site's fields: `report_type`, `r_email`, `r_details` and
  `sendreport=Send Report`. It goes out on the app's own URL session, so it carries the same sign-in as posting a
  comment.
- **DD-03:** "Sent" means a 2xx final response whose body no longer contains `#reportform`. Anything else is
  "failed". The site's success page has never been seen, and owner msg 1933 rules out a real submission, so this rule
  rests on an assumption (Research OQ-1).
- **DD-04:** `{date}` in the prefill is the comment's date as `yyyy-MM-dd HH:mm 'UTC'` (`en_US_POSIX`, UTC). The
  prefill adds no comment number or link: Camo's file leaves that to Pluso, and the wording stays as written.
- **DD-05:** Email check on Send: one `@`, a non-empty local part and a domain containing a dot. No other format rule;
  the site does its own check.

  `https://<site>/g/<gid>/<token>/?report=select` from a validated gallery URL, and `siteName(for:)` gives `{site}`.
  A per-type variant is added next to it.

  `CommentsView:96`.
- **Detail screen:** `DetailReducer.Destination.reportPage(URL)` (line 40), `DetailReducer+Actions:76-77`, with the
  sheet at `DetailView:241`.

- **`PostCommentView`** provides the sheet toolbar pattern (`Button(role: .close)`, inline title).
- **`FirstLaunchGateView`** (`AppFeature/FirstLaunch`, :80-96) is the reference for the pinned bar: the scroll view
  with `.scrollEdgeEffectStyle(.soft, ...)` and `.safeAreaBar(edge: .bottom)`, with no bar background.

  `NetworkingFeatureTests/AccountRequestBaselineTests.swift` use `CountingStubProtocol` and `expectFormRequest`.

- TCA reducers with `@Dependency` clients (`@DependencyClient`). Tests run with `TestStore` and `.noop` clients.

- SwiftLint runs strict with no suppressions. Every `.xcstrings` key is filled for all six locales.
- The module chain: DetailFeature → NetworkingFeature → ParserFeature.

### Integration Points
