# EhPanda: in-app Report form copy, six languages (APPROVED msg 1975)

Author: Camo. Status: FINAL, approved by the owner msg 1975 (includes "Send Report", msg 1960). Decision it's written for: owner msg 1931 ("Our own form"). Facts: Pluso msg 1934 (ehpanda-report-form-facts.md).
Placeholders: {site} = E-Hentai or ExHentai, {name} = comment author. Pluso converts them to positional %1$@ / %2$@ as before.
Tone as the rest of the app: de du, ko -습니다, ja です/ます, zh plain 你. zh-Hant ellipsis is ⋯ (matches existing strings).

## Terms (unchanged from the approved comment copy)

report = melden / Meldung · 신고 · 通報 · 举报 · 檢舉
the site's staff = das Team von {site} · {site} 운영진 · {site} の運営チーム · {site} 的管理人员 · {site} 的管理人員

New: being banned by the site. It must NOT use our "block" word, or "Block" in the comment menu would read like the site's punishment:
banned = gesperrt · 이용이 제한됨 · 利用を停止される · 封禁 · 停權  (not blockiert / 차단 / ブロック / 屏蔽 / 封鎖)

## Reused, already approved (no new strings)

- Sheet title and menu item: comment.report "Report on {site}". Same words on the menu and on the sheet.
- Fallback / failed / copyright button: comment.report.open "Open Report Page". It says exactly what opens, so I'd rather reuse it than add "Open on {site}".
- Failed alert: retry "Retry", comment.report.open "Open Report Page", cancel "Cancel". Top-left of the sheet: the system Close button (X glyph, iOS supplies its own label), so no string from us there (settled with Colo, Ato msg 1973).
- No longer needed once the form ships: comment.report.confirm_title and comment.report.confirm_body (the old "mention it's about a comment" dialog). The form fills that in itself, so the dialog goes.

## Dropped (owner msg 1975)

No gallery Report button, now or later, unless distribution requires it: "Adding comment report is purely for Apple guidelines. And I don't want people report galleries." So these don't ship: report.reason.updates, report.reason.restore, report.reason.copyright, report.help.updates, report.help.restore, report.help.copyright, and the Copyright-picked layout. Shipping reasons: report.reason.child and report.reason.illegal only. report.help.illegal_warning keeps its "including copyright requests" clause: it's the site's own warning about misuse.

## Open questions: resolved

Owner msg 1950 ("Illegal content only"): from a comment, only report.reason.child and report.reason.illegal are offered, with the warning. Copyright and the two technical reasons are shown only when reporting the gallery itself. Spam is handled by Block; there is no spam reason. Pluso msg 1939 agreed with 2 and 3. If no gallery-level Report entry ships, report.reason.updates / .restore / .copyright and report.help.updates / .restore / .copyright go unused. No wording changes from this decision.

Original questions:

1. Spam. The site has no "spam" or "harassment" reason, and its warning says reports that aren't about illegal content can get the reporter banned. A plain spam comment fits none of the five types. Someone should decide what a spam report from a comment should pick, or whether comment reports show only the two illegal-content reasons. I haven't written a "spam" reason because the site has nothing to map it to.
2. Undisown. "Restore or split the gallery" covers the site's help text for that type. "Undisown" isn't explained by the site and only matters to uploaders, so it's not in the label. The request still goes as the site's own type.
3. The two Technical reasons (updates, restore/split) are about the gallery, not a comment. Suggest hiding them when the form is opened from a comment.
