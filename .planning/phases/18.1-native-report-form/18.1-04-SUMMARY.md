# Phase 18.1 Plan 04: Report form view and UI tests Summary

**Report on a comment now opens EhPanda's own Report form, drawn per UI-SPEC C-13 on iPhone and iPad. It shows two
illegal-content reasons, an email that is never stored, the English prefill and the pinned Send Report button, and it
falls back to the site's page. Each of the nine C-13 states has a UI test on stubbed network, and the screenshots were
checked against frames 25–31, 33 and 34.**

## Accomplishments

- **The sheet (Task 1, `781536765`, fixed in `0866ba1a8`):**
  - `ReportFormView` follows C-13 section by section: intro, Reason (two rows with a trailing accent checkmark and
    `.isSelected`), Email with its keyboard modifiers and the red invalid footer with an announcement, Details with
    `.lineLimit(5...)` and the footers that depend on the reason.
  - Loading appears after 0.3 s. Unavailable is a `ContentUnavailableView` with no actions inside it. Sent shows the
    64pt checkmark with a bounce (none under Reduce Motion), a success haptic and VoiceOver focus on the title, with
    no Close or title. Failed is an alert over the kept form.
  - Accessibility identifiers: `report_form`, `report_reason_<raw>`, `report_email`, `report_details`,
    `report_primary_button`, `report_loading`, `report_unavailable`, `report_sent`, `report_illegal_warning`.
  - CommentsView and DetailView present `.reportForm` as a sheet. The `reportPage(URL)` cases and sheets are gone.
    The form presents `ReportPageSheet` itself.
  - Catalog: `comment.report.confirm_title` and `_body` are removed. `18-copy-check.py` lists them as retired: a key
    that is absent passes, a key that is present is a finding. A self-test case covers this (22/22 cases).
- **Stubs (Task 2, `5eff640fa`, fixed in `125b92bcf` and `f45355fd9`):** `EHPANDA_UITEST_REPORT_SCENARIO` is read only in DEBUG and only
  when the network is stubbed. Any other launch, or an unknown value, gets `ready`. Report queries are routed before
  the `/g/` branch (F-2). Three fixtures were added, and `UITestStubTests` covers the routing for each scenario.
- **UI tests (Task 3, `d5ba85692`, fixed in `41398e24e`, `f45355fd9` and `cfff03df8`):** `ReportFormUITests` has nine tests, one per C-13 state.
  Each one launches stubbed with a request log and attaches screenshots.
  - `CommentModerationUITests` now expects the form to open directly from the comments list and from a Detail strip
    card, with no alert.
  - `AccessibilityAuditUITests.testReportFormAudit` audits the ready form.

## Deviations from Plan

1. **[Rule 1] slowLoad holds for 6 s, not 2 s (`125b92bcf`).** The spinner appears after 0.3 s, but the test can read
   it only once the sheet is up, about 3 s after the comment's menu. With a 2 s hold the form finished loading first.
2. **[Rules 1/2] View fixes from the frame check (`0866ba1a8`).**
   - Reason rows were drawn in the tint; they now use primary text.
   - The intro was faded twice inside the header.
   - Retry was not the alert's default button.
   - The sending spinner was small.
   - The top scroll edge was missing.
   All were fixed in the view. None is recorded as an accepted difference.
3. **[Rule 1] ⌘↩ in the iPad test (`41398e24e`).** On the iPad simulator, `typeKey(.return, modifierFlags: .command)`
   never reached the button's shortcut, while `"\n"` with Command did. Probes showed that ⌘A and plain keys arrive.
   Only the test changed; the view's `.keyboardShortcut(.return, modifiers: .command)` stays.
4. **Test Details text.** The typed Details line is "The linked page hosts illegal content.", matching the refreshed
   frames' illegal-content wording rather than a spam reason, which C-13 excludes.
5. **[Rule 3] Files outside the plan's list.**
   - `DetailReducer+Actions.swift`: Detail's present-the-form branch now sends the form's `.task`, as Comments does.
   - `CommentModerationReducerTests.swift` and `CommentsReducerTests.swift`: the existing destination tests receive
     that load.
   - `EhPandaUITests/Support/UITestConstants.swift` (listed) holds the scenario key.
6. **The refreshed mockups 25, 26, 27, 29 and 34** are in the docs commit. See the frame comparison.
7. **[Rule 1] holdSend holds for 10 s, not 3 s (`f45355fd9`).** In the full pad run, `testSendingLocksTheSheet` failed
   with "A swipe down closed the sheet". The activity log showed the swipe 3.7 s after the tap. The 3 s hold had
   already ended, so the sheet was in Sent, where a swipe correctly dismisses it. The test now waits up to 20 s for
   Sent.
8. **[Rule 1] The UI tests scroll to the linked comment when the link stops short (`cfff03df8`).** In one phone class
   run, `testTheLargestTextSizeKeepsTheButtonInReach` failed all three attempts with "EhPanda did not present
   comment_cell_6894060". The hierarchy showed the comments list at its first three comments: at AX5 the link's
   `scrollTo` had not reached the comment. Run alone, the test passed. `openReportForm` now waits 15 s as before,
   then swipes the list up (at most 8 times) until the row exists. The app's link scroll is Phase 18 code and is
   unchanged. It is recorded below as an open item.
