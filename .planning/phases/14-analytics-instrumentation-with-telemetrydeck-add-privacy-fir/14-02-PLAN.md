Each question below carries the recommendation and the reasoning behind it. Answering "recommended" for all five is a valid single response.

**Q1 — D-07's category list omits two `Category` cases.**
D-07 permits "the E-Hentai category enum" and then parenthetically lists nine names. The actual enum in `AppPackage/Sources/AppModels/Gallery/Category.swift` has eleven cases: the parenthetical omits `imageSet` ("Image Set") and `private` ("Private"). The owner's framing was "collect everything that's not privacy sensitive", and the named entity was the enum itself — both point at incomplete recitation rather than deliberate narrowing. CONTEXT is explicit that D-07 must not be tightened, and silently dropping two cases would be tightening.
*Recommendation:* ship the full eleven-case enum. (Note `Category.private` is already a display-only bucket in this codebase and may simply never occur in practice.)

**Q2 — Are per-namespace tag counts bucketed?**
D-07 says "which namespaces are present … and how many of each". D-08 says counters ship as buckets, with exactly one stated exception (search keyword length). Reading D-08's exception list as exhaustive is the reading that honors both decisions.
*Recommendation:* bucket the per-namespace counts through `CountBucket`. This is a one-line confirmation, not a re-litigation of D-07.

**Q3 — The identifier salt.**
The SDK's `Config.salt` defaults to an empty string. Its own documentation recommends a random 64-character string, and warns that changing it later makes every existing user look new — resetting retention, DAU and MAU permanently. No locked decision covers this.
*Recommendation:* generate a random 64-character salt now and store it in the same gitignored `Config/Analytics.local.xcconfig` as the app ID, surfaced through a second `Info.plist` key. It costs one line and is effectively unfixable later.
*Alternative:* accept the empty default permanently — simpler, and the identifier is already hashed on-device and re-salted server-side, so the marginal gain of an app-side salt is real but modest.

**Q4 — A SwiftLint rule enforcing D-12's single-import boundary.**
D-12 says only `AnalyticsClient` imports the SDK. Today that is a convention held up by review. A `custom_rules` entry rejecting the SDK import outside that module would make it structural — a second layer behind D-09's type wall.
*Recommendation:* add it. But every custom rule in this repository has been a deliberate, owner-approved addition, so this is a proposal rather than an assumption. If declined, the type wall alone still stands and plan 14-16's task is dropped.

**Q5 — Where exactly does the D-09 "no bare String" wall sit?**
D-09 says `AnalyticsClient`'s public API must not accept a bare `String` anywhere, so a contributor cannot leak a title, keyword or URL by accident. Two payloads need content-derived values that only the app domain can compute: the per-namespace tag counts for an opened gallery (derived from `[GalleryTag]`) and the search shape (word count, tag-syntax flag, exact length — derived from the keyword string).
The plan's reading: the wall protects the **signal-carrying** API. `AnalyticsClient.send` accepts only `AnalyticsSignal`; every `AnalyticsSignal` case carries only closed enums, `Bool`s, bucket enums, or the one exact `Int` D-07 permits. The content-reading derivations live behind two named value types with derivation initializers (`TagNamespaceCounts(tags:)` and `SearchShape(keyword:)`) inside the `AnalyticsClient` module, which are the only content-accepting entry points, are exhaustively tested to prove nothing content-bearing survives, and are marked in source as the audited reduction boundary.
*Rationale:* the alternative — deriving at the call sites — spreads the reduction across five gallery-open sites and every search site, which is strictly worse for both auditability and correctness.
*Recommendation:* accept this reading. If declined, the fallback is to move both derivations into `AppModels` as pure functions returning already-closed types, so `AnalyticsClient`'s surface never sees a `String` at all — more files, same guarantee.
