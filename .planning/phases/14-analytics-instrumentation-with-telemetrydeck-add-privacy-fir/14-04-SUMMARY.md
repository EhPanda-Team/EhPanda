## Decisions Made

- **The salt is not generated by this plan.** Generating it into a tracked file would commit a write-once value the owner must own; generating it into the untracked local file would presume this machine is the release machine and would pair a real salt with an app ID that must stay empty. `14-USER-SETUP.md` gives the owner the one-line command and the write-once warning instead.
- **The pbxproj edit is its own commit.** It touches a generated, merge-hostile file, so it can be reverted without unwinding the source changes.
- **`requirements-completed` is empty.** ANALYTICS-01 is phase-wide and plan 14-17 closes it; this plan supplies one precondition. This matches plan 14-03's handling.
- **The private helper trims before testing for emptiness.** An override containing `TELEMETRYDECK_APP_ID = ` with a trailing space, or a value pasted with a newline, would otherwise present as a non-nil credential that the SDK would reject at runtime — a failure mode with no visible symptom.

## Research Assumptions Closed

- **A3 — `#include?` of an absent file is a silent no-op.** Confirmed. A full build with no `Config/Analytics.local.xcconfig` present emitted `BUILD SUCCEEDED` with zero warnings of any kind, and zero lines matching `unable to open base configuration` or `unable to open included file`. The plan's fallback (dropping the include and having the release machine edit the tracked file locally) was not exercised.
- **A2 — `Bundle.main` from an SPM module resolves to the app bundle.** Confirmed, and specifically confirmed against a *built* bundle rather than the source plist.

## Issues Encountered

- The first PlistBuddy read landed on a stale `Release-iphonesimulator` bundle from an earlier session, where neither key existed — a false negative that would have read as "substitution does not work". Resolved by reading the `Debug-iphonesimulator` product the current build actually produced. Worth knowing: an absent key and an empty key are different signals here, and only the second means the substitution ran.
- `xcodebuild -showBuildSettings` omits settings whose value is empty, so it cannot be used to confirm the credential-free state — it shows nothing either when the variable is empty and when it was never declared. It is only useful for proving the override *wins*, which it did.
