<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Owner verification of live delivery and of silence without a credential</name>
  <what-built>
Phase 14 shipped a privacy-first analytics client behind a closed signal vocabulary:
- A new `AnalyticsClient` module — the only file in the repository that imports the vendor SDK.
- A thirteen-case signal enum whose every payload is a closed enum, a boolean or a bucket, so free-form text is unrepresentable.
- Instrumentation across navigation, search, reading, downloads, errors and login, emitted from reducer actions only.
- Six app settings attached to every signal, re-read at emission time.
- A build-time credential that is not committed; without it the client is a total no-op.

Everything above is covered by automated tests, including sentinel-based assertions that no gallery title, search keyword, tag value or credential can survive into a signal. Two things remain that no test can check.
  </what-built>
  <how-to-verify>
**Check A — nothing is sent without a credential (this is the direct check on the no-op guarantee).**
1. Confirm no local analytics configuration file is present: `git status --porcelain Config/` should show nothing, and `ls Config/` should list only the committed default.
2. Build and run the app on a device or simulator.
3. With a network inspection proxy attached (Proxyman, Charles, or the equivalent), exercise several instrumented flows: open two Home sections, switch tabs, perform a search, open a gallery, open and close the reader.
4. **Expected:** zero requests to the analytics ingestion host. Not "a few harmless ones" — zero. Any request at all means the gate is not holding and the phase is not done.

**Check B — signals arrive when a credential is present.**
5. Create the local analytics configuration file with the real app ID (and the salt, if one was chosen), following the README's build section.
6. Rebuild and run.
7. Exercise the same flows as step 3.
8. In the vendor's web console, confirm the corresponding signals appear. They will be marked as testing-mode signals from a debug build, which is expected.
9. **Inspect the payload of at least three arrived signals, including one search signal and one gallery-detail signal.** Confirm by eye that no gallery identifier, token, title, URL, search keyword text, tag value, username, credential or file path appears in any field — and that the search signal shows a word count, a tag-syntax flag, a length and a bucketed result count rather than the query.
10. Confirm each signal carries the six app-setting parameters, and that changing one of those settings and emitting again shows the new value.

**Check C — the disclosure matches reality.**
11. Read the README's Analytics section against what you just saw in the console. Confirm the never-collected list is accurate and that nothing arrived which the section does not mention.

**After verifying:** delete or move the local analytics configuration file so the working tree returns to its credential-free state, and confirm `git status` is clean.
  </how-to-verify>
