    `CountBucket.init(count: Int)` — total, no gaps, no overlaps:
    - count <= 0 → `.zero`, rendering `"0"`
    - count == 1 → `.one`, rendering `"1"`
    - 2...5 → `.twoToFive`, rendering `"2-5"`
    - 6...20 → `.sixToTwenty`, rendering `"6-20"`
    - 21...50 → `.twentyOneToFifty`, rendering `"21-50"`
    - 51 and above → `.fiftyOnePlus`, rendering `"51+"`
    Negative input clamps to `.zero` rather than trapping (a negative counter is a programming error, not a user event, and analytics must never crash the app).

    `DurationBucket.init(seconds: TimeInterval)` — total, no gaps, no overlaps:
    - seconds < 10 (including zero and negative) → `.underTenSeconds`, rendering `"0-10s"`
    - 10 ..< 60 → `.tenToSixtySeconds`, rendering `"10-60s"`
    - 60 ..< 300 → `.oneToFiveMinutes`, rendering `"1-5m"`
    - 300 ..< 1200 → `.fiveToTwentyMinutes`, rendering `"5-20m"`
    - 1200 and above → `.overTwentyMinutes`, rendering `"20m+"`

    Both enums are `CaseIterable`, `Equatable`, `Sendable`, with a `String` raw value carrying the rendering above. Both boundary values on every edge are asserted in the tests (e.g. 1/2, 5/6, 20/21, 50/51 for counts; 9.999/10, 59.999/60, 299.999/300, 1199.999/1200 for durations).
