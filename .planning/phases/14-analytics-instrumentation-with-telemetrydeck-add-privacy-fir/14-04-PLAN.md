<objective>
Plumb the TelemetryDeck app ID (and, per D-17, the identifier salt) from an untracked local build configuration through `Info.plist` into a Swift accessor, so an absent credential resolves to `nil` and the analytics client can no-op on one check.

Purpose: D-13. The repository is public and the release machine is the only build that should reach the owner's dataset. This is also the one file group in the phase with **no in-tree analog** — `Config/` does not exist today and the app target has no base configuration reference — so the plan budgets explicit verification for the two unverified research assumptions this path rests on.
Output: a committed `Config/Analytics.xcconfig`, a gitignored local override, a wired base configuration reference, two new `Info.plist` keys, and an `AppInfo` accessor with tests.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-14-03 | Tampering | owner's analytics dataset | medium | mitigate | D-13's absent-credential gate: the tracked xcconfig declares an empty default, the override is gitignored, and `AppInfo.telemetryDeckAppID` returns nil — which plan 14-06 resolves to a no-op client before the SDK is touched. Proven by a unit test asserting nil under the test host and by a `PlistBuddy` read of a built bundle. |
| T-14-06 | Tampering | analytics ingestion endpoint | low | accept | The app ID is extractable from any released build. It is a write-only ingestion key, not a secret; D-13 reasons about this explicitly and accepts it. No mitigation in scope. |

| T-14-07 | Repudiation | anonymized identifier derivation | medium | mitigate | The salt (D-17) travels the same untracked path as the app ID, so it is set once on the release machine and never enters history. |
