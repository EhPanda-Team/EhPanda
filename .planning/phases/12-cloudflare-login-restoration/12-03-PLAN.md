  <action>
    Create `ChallengeWebView.swift` in SettingFeature/Components. Follow WebView.swift's shape —
    module-scope private `Logger(category:)`, a `UIViewControllerRepresentable` struct holding
    `url: URL` and `onClearance: (CloudflareClearance) -> Void`, an embedded
    `UIViewController` subclass that owns the `WKWebView` (sets it as `view` in `loadView()`,
    loads the URL) — with these deliberate differences:

    1. Build a `WKWebViewConfiguration` whose `websiteDataStore` is
       `WKWebsiteDataStore.nonPersistent()` BEFORE creating the web view. Rationale (comment it):
       criterion C5 — everything the challenge run mints, including cf_clearance, stays in memory;
       nothing reaches WebKit's on-disk cookie database, so a relaunch provably starts clean.
    2. Register a `WKHTTPCookieStoreObserver` on that configuration's
       `websiteDataStore.httpCookieStore`. The store does NOT retain observers (SDK contract), so
       the controller owns the observer strongly and removes it on teardown (deinit or
       viewDidDisappear-equivalent in UIKit terms — UIKit controller lifecycle is fine; the
       `lifecycle_modifiers` lint rule bans SwiftUI `.onAppear`/`.task`, which this file must not
       use).
    3. In the observer's cookies-did-change callback (main thread per the SDK's UI-actor
       annotation): `getAllCookies`, find a cookie named `cf_clearance` with a non-empty value,
       and — guarded by a one-shot latch so the pair is reported exactly once — read the exact
       effective UA of THIS web view via `evaluateJavaScript("navigator.userAgent")` (Pitfall 1:
       Cloudflare binds the clearance to the solving client's UA; read it from the same instance,
       inside the callback, before any dismissal). Only set the latch after a successful String
       result, then call `onClearance(CloudflareClearance(cookieValue:userAgent:))`; if the JS
       read fails, leave the latch unset so the next cookie change retries. Note the SDK selector
       mapping: ObjC `cookiesDidChangeInCookieStore:` imports as Swift `cookiesDidChange(in:)` —
       confirm the exact signature against the compiler.
    4. Do NOT replicate WebView.swift's navigation-finish cookie copy into the shared system
       cookie jar (the `getAllCookies` → per-cookie set loop in its navigation delegate) — that
       write is the exact D-04 violation this wrapper exists to avoid. The wrapper needs no
       navigation delegate at all unless the compiler requires one; keep it minimal.
    5. Name the coordinator `Coordinator` if one is needed (do not copy WebView.swift's
       misspelled type name); prefer no coordinator if the controller can own the observer.

    Logging: milestone notices only (e.g. challenge page loaded / clearance captured) with no
    cookie value at any privacy level (Phase 8 gate). Imports sorted per `sorted_imports`;
    trailing closures per `single_line_trailing_closure`; no optional-try.
  </action>
