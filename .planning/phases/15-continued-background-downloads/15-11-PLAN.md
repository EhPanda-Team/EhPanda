**Spy staging verbs (`BackgroundProcessingClientSpy` in `DownloadFeatureTestSupportTypes.swift`),**
all state behind the existing Mutex, each a small named type with a doc comment per house style:

- `armStartGate()` returning a `StartGate` handle. One-shot: the next start call performs its
  full recording — count, strings, minted session id, stored continuation — and then suspends
  until released, returning its handle only after release. `StartGate` exposes
  `entered() async` (resumes once the gated start has recorded and parked) and `release()`.
  Implement both rendezvous points as AsyncStream continuations stored in the spy's state — the
  suite's determinism rule allows no polling and no sleeps, and neither the new code nor its
  comments may name the suite's polling helper or the clock-sleep API (a grep gate below holds
  the file to that). Recording fully before
  parking is deliberate: the held start must already be visible in `startSessionIDs` so the case
  can distinguish it from the successor's, and the successor's continuation then supersedes the
  held one exactly as the store supersedes an abandoned session.
- `refuseNextStart()`. One-shot: the next start call records the call (count and strings — the
  coordinator did call start) but mints no id, stores no continuation, and returns nil,
  mirroring the store's re-entry refusal, which burns nothing.
