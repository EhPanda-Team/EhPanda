<objective>
Close G-15-9 (blocker; violates SC2 and the project's root-cause rule that an error must never be
swallowed into a destructive action). `reconcileWorkingManifestAgainstPageFiles` treats a
best-effort file probe's empty answer as authoritative evidence that page files are gone, and
acts irreversibly: it blanks recorded content hashes, persists the manifest, re-indexes the
record, and (since 15-29, via the D-G7-01 bracket) withdraws from the session floor. The probe
swallows failure at three verified levels: `existingAssetFileURLs` returns `[]` on ANY
`contentsOfDirectory` failure with an explicit comment that the error is deliberately not logged;
`existingPageRelativePaths` drops any page whose file fails `sanitizeAssetFileIfNeeded`; and
`sanitizeAssetFileIfNeeded` falls back to `canReadNonEmptyFile`, which returns `false` on ANY
open/read failure — descriptor exhaustion, transient `EBUSY`, a data-protection denial while the
device is locked, which is precisely the state a backgrounded continued-processing session runs
in. `prepareWorkingSeed` computes `existingPages` once and hands that single dictionary to the
reconciliation, so ONE failed enumeration blanks EVERY claimed page in one pass, unlogged.
Before D-G5-01 the same empty answer was harmless (it only caused a re-fetch); it now mutates
durable state.

The fix, per the gap's mandated shape:

1. **Surface the failure.** `existingAssetFileURLs` returns an optional: nil means the
   enumeration failed (including a missing folder — in the reconciliation's context the manifest
   was just read from that folder, so an unenumerable folder is a contradiction, not an empty
   listing). A new `pageFileScan(folderURL:manifest:)` returns a small `PageFileScan` struct —
   the pages dictionary plus `scanSucceeded` — and `existingPageRelativePaths` forwards to it,
   preserving the `[]` fallback for the ~10 existing probe callers whose behavior must not
   change.
2. **Require a positive signal before destroying.** The reconciliation refuses to blank when the
   scan failed, and refuses wholesale blanking — a pass that would blank EVERY claimed page of a
   folder whose manifest read succeeded — even when the scan nominally succeeded (a successful
   listing of the manifest's own folder that shows none of its claimed pages is the signature of
   per-file probe failure, e.g. descriptor exhaustion failing every sanitization). The deliberate
   tradeoff is documented at the refusal: a genuinely all-pages-vanished repair falls back to the
   pre-D-G5-01 arc — `existingPages` still carries the truth, the run re-fetches every missing
   page, and the record's honesty catches up at flush time — which is accepted against the
   alternative of letting a transient failure destroy every hash. `resumeMode`'s
   `storage.validate` branch remains the route that still resolves `.repair` for such a record
   (its why-still-reachable note is 15-32's IN-01 item).
3. **Log what was destroyed.** A blanking that proceeds logs at `.notice` with the blanked count
   and the hash-masked gid, so a device archive can show whether a blanking was real.
4. **No withdrawal on refusal, by construction.** A refusal moves no index record, so 15-29's
   delta-keyed bracket withdraws zero. No compensating code exists to get wrong.

Purpose: the coordinator can no longer destroy durable download state on a probe's non-answer,
and when it does destroy state, the act is observable.
Output: the surfaced-failure store API, the two refusal guards with their documented tradeoff,
the `.notice` log, one wholesale-failure regression watched to fail first, and a green full run.
</objective>
