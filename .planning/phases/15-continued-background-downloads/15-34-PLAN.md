<objective>
Close G-15-14 (blocker; violates SC1 — a trap kills the process mid-run with the fallback tier
deleted, so nothing resumes the download — and SC3's no-lost-work clause). Two sites build
`1...payload.galleryDetail.pageCount` from a value the same module guards as possibly zero in two
other places: `pendingPageIndices` (`DownloadClient+ExecutionSupport.swift:673` at planning time)
and `initializePageDownloadState` (`DownloadClient+PageDownload.swift:81-83`). `1...0` is an
invalid `ClosedRange` and traps at runtime. That zero is a reachable input is established by the
module itself — `makeInitialManifest` branches on a positive page count before building its page
dictionary, and `reusableExistingManifest` guards the same value — and no guard sits between the
queue and the run: `enqueue` validates the folder name and nothing about the page count, while
`performDownload` runs against a FRESHLY fetched payload, so the count that reaches the range is
a new parse. An expunged gallery, a partially rendered detail page, or an upstream HTML change
therefore kills the app instead of failing the download.

The fix, per the gap's mandated shape plus its two deliberate decisions (together D-G14-01):

1. **Guard both sites** to return empty, matching the sibling guards' shape.
2. **Reject at enqueue.** A zero-page payload never enters the queue: the run could not finish
   it, and a queue holding unfinishable work is a standing liveness hazard.
3. **Settle the zero-page refetch as failed.** The mid-run question the gap raises is decided:
   a freshly fetched detail with no page count throws at `fetchLatestPayload`'s existing guard
   boundary (the missing-gallery-URL guard is two lines above), so the run's established catch
   settles the download as failed — a visible, honest error state — rather than silently
   no-opping into a 0-of-0 record that would read complete.

No new suspension is introduced anywhere: every added guard is a synchronous check inside an
existing function (mandate 3 does not trigger — no previously synchronous tail gains an await).

Purpose: a degenerate upstream parse can no longer kill the process; it produces a visible
failed download the user can retry.
Output: four guarded/deciding sites, a new three-case zero-page suite, and a green full run.
</objective>
