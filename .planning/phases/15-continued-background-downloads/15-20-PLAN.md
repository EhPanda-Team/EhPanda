<objective>
Close UAT gap **G-15-2**: with several galleries queued, the first one to finish makes the system card
report completion and collapses its subtitle to the remaining gallery count.

The cause is an accounting basis, not a clamp. `schedulableProgress()` sums the numerator and the
denominator over the *currently schedulable* gallery set, and `settleCompletedDownload` removes a
finished gallery from the queue store — so a completion takes that gallery's pages out of **both**
sides of the fraction at once. The monotonic floor `lastPushedCompletedPageCount` then holds the
numerator at its pre-shrink queue-wide value, and `pageCount = max(snapshotTotal, completedPageCount)`
lifts the denominator back up to meet that stale floor. The pushed pair becomes `P / P` — a literal
100% card — and cannot advance again until the survivors collectively re-earn `P` pages.

That is not cosmetic. Every later flush pushes the same frozen `completedUnitCount`, which destroys
the one liveness signal the scheduler reads; a task that appears stalled is expired first, and a
forced expiration routes to `pauseAllSchedulable` and pauses every gallery the user never touched.

**The fix is a cumulative, session-scoped retirement ledger.** When a gallery leaves the schedulable
set, the pages it finished are folded into a per-gallery ledger that is added to **both** the
numerator and the denominator of every later push. A completed gallery retires its whole page count,
so the denominator does not move when it leaves and the numerator rises naturally across the gallery
boundary. The `max()` floor stays, demoted to residual defence.

**D-G2-01: a gallery that leaves by pausing, deleting or being cancelled retires exactly the pages it had already finished — added to both sides — and nothing more.** Its unfinished pages leave the
denominator with it. Three reasons, and they are why one formula covers every departure:

1. The denominator must describe work this session has done plus work it still intends to do. Pages
   of a paused or deleted gallery will never be done in this session, so keeping them would pin the
   card permanently below 1.0 — the mirror image of the defect being fixed here.
2. Dropping the finished pages as well would rewind the numerator, which is the stall signal the
   scheduler reads, and would immediately re-open the same joint-unsatisfiability the two clamps
   already have.
3. Symmetric retirement is the only rule under which the numerator never rewinds *and* the fraction
   reaches 1.0 exactly at queue drain. A completed gallery is that same rule with nothing left over —
   finished equals total — which is why no call site has to classify *why* a gallery left.

**Why the ledger is maintained by a push-time membership sweep and not by a hook in
`settleCompletedDownload`.** Galleries leave the schedulable set through at least six paths:
completion settle, the incomplete-error dequeue, pause, delete, the queued-work-item cancel, and the
expiration pause-all. Instrumenting the one path the user happened to report would close this gap and
leave the others — the exact shape that made three earlier gap rounds in this phase refill. The sweep
observes membership at the single point that already reads the schedulable set, so every departure is
covered by construction and a rejoining gallery is covered too.

Purpose: the phase's one failing UAT check, severity major, blocking phase completion.
Output: the coordinator's session progress reported over a basis that no longer shrinks, and a suite
that fails if the shrinking basis returns.
</objective>

**3. The retirement reconcile.** A private function on the coordinator that takes the current
per-gallery finished map and, in this order:

- drops the ledger entry of every gallery present in the current map. A gallery that rejoined is
  counted by the live sum again, so leaving it retired would double it.
- computes the departed set as the keys of `observedSchedulablePages` absent from the current map.
- when that set is non-empty, reads those galleries' current records with `indexedDownloads(gids:)`
  and retires each one at `min(max(completedPageCount, 0), pageCount)` — the authoritative finished
  count. A gallery with no record left (it was deleted) retires at its last observed value instead.
  Reading the record rather than trusting the last observation is what makes a completed gallery
  retire its full page count even if it finished between two pushes.
- replaces `observedSchedulablePages` with the current map, so each departure is detected exactly
  once and a retired value is then frozen until that gallery rejoins.

Document one consequence on this function alongside D-G2-01, because it looks like a leak to anyone
tracing where a gallery's pages went: a gallery that both joins and fully departs between two pushes
is never observed, so it enters neither the live sum nor the ledger. That is correct rather than
lossy — it was never part of the fraction, so its absence rewinds nothing and double-counts nothing —
and the alternative, a ledger fed from every queue mutation instead of from observed membership,
would have to distinguish work this session actually reported from work it never saw.

The arithmetic, with the ledger's summed value added to both sides. **The live sums enter it raw.**

- raw session completed = live raw completed + retired total
- raw session total = live raw total + retired total
