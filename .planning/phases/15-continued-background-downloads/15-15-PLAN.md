<objective>
Make the SC2/SC3 reentrancy fix falsifiable. 15-VERIFICATION.md is explicit that the existing
foreign-id case at `DownloadContinuedSessionIdentityTests.swift:109-137` "returns at the first
guard and never enters the suspension window, so it does not prove the behavior", and it asks for
"a gated interleave that enters pause, performs a resume/retry, then releases the stale pause".
This plan writes exactly that, on the control token plan 15-14 built.

The first case enters the real expiration path through the real event handler, holds it inside the
awaited task cancellation, performs an ordinary retry for the same gallery, and then releases. It
asserts both halves of CR-03: the retry's queue intent survives the stale pause's return, and the
retry actually mobilizes the queue and gets the session it asked for instead of being silently
refused while its gallery was blocked.

The second case is the guard's boundary: a user-initiated pause with the same interleaving retry
must still win, because the generation guard belongs to expiration ownership alone. Without it, the
fix could quietly change how pausing by hand behaves and no assertion would notice.

Purpose: the defect class this round exists to close is invisible to state assertions taken before
or after the fact — both halves of the coordinator's state stay self-consistent while a user's
action is erased. Only a staged suspension can see it.

Output: a new interleave suite with two deterministic cases, plus the round's closing full-suite and
lint gates.
</objective>

**Case `testAResumeInsideAStaleExpirationPauseSurvivesAndMobilizesTheQueue`:**

1. Build the blocking fixture with the session spy and the cancellation-holding mode, so the runner
   stays parked after its task is cancelled. Defer both the temporary-directory removal and the
   control release, in that order, so an early exit unblocks the runner before the directory goes.
2. Start the session with `ensureContinuedSession()`; require the coordinator session id and assert
   the spy recorded one start.
3. Put the download in flight through the public queue-resume entry point, then await the control's
   started rendezvous. The active task is now genuinely installed — the state the expiration path
   has to cancel.
4. Launch the expiration as a `Task` calling `handleContinuedSessionEvent` with the expired event
   and the captured session id. Driving the real handler rather than the pause-all loop is
   deliberate: the ordering under test includes the handler ending the session before pausing
   anything, which is what makes the coordinator's live-session field nil during the window.
5. Await the control's cancellation-observed rendezvous. The stale pause is now parked inside its
   awaited task cancellation, past the first guard and before the settled write — the exact window
   the review describes.
6. Perform the interleaving user action: retry the same gallery through the coordinator's public
   retry entry point with the initial mode, and require its result. Assert here, while still inside
   the window, that the spy's start count is unchanged — the gallery is scheduling-blocked, so this
   tap could not start a session at the moment it asked. That assertion is the second half of the
   defect stated plainly, and it is why the abandoned pause owes a convergence.
7. Release the control and await the expiration task.
8. Assert the retry survived and was honored, on four axes: the persisted queue still contains the
   gallery, its queued mode is still recorded, the spy's start count is now two — the deferred
   ensure gave the tap its session — and the coordinator reports a live session. Before the fix the
   settled write cleared both queue facts and no second start ever happened.
9. Assert nothing completed the successor: no finish record names the most recently recorded start
   id.

Doc comment on the case: name CR-03 and the verification's replacement item, describe the six-step
interleave in one sentence, and state what the pre-fix code did — cleared the user's fresh intent on
resume and left a tap that reported success having mobilized nothing.

**Honest scoping of the case this replaces.** The verification says the existing foreign-expiration
case in `DownloadContinuedSessionIdentityTests` "returns at the first guard and never enters the
suspension window". Keep the case — the early-return guard it exercises is real and worth pinning —
but stop it claiming more than it does: rewrite its doc comment to say exactly what it covers, that
a pause-all belonging to a superseded session stops before its first pause, and to name the new
interleave suite as the place the suspension window itself is covered. Do not weaken any of its
assertions; this is a documentation correction, so that no reader mistakes the pair for one case
doing both jobs.
