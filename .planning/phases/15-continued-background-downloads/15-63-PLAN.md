<objective>
Close CR-03 by moving folder rename's filesystem mutation behind a store-owned direct-child confinement boundary.

`oldName` is public client input, even when today's UI normally supplies a listed folder. The boundary must reject lexical traversal before resolution, reject symlink redirection after resolution, and re-check immediately before mutation. Normalizing an invalid source is not acceptable because it can select a different directory than the caller named.

Purpose: prevent folder rename from moving a sandbox-accessible source outside the persisted download root.
Output: confined store rename and security regression coverage.
</objective>

## Artifacts this phase produces

- New `DownloadStore.renameUserFolder(oldName:newName:) throws` operation owning validation, containment, symlink checks, existence/collision checks, and `moveItem`.
- New private `validatedDirectUserFolderURL(named:requiresExistingDirectory:)` helper in `DownloadStore+Operations.swift`.
- New folder-operation tests for `..`, traversal, absolute paths, nested components, normalization-changing source names, source symlinks, and valid direct children.
