<objective>
Close the coordinator-side half of the SC1 session-lifecycle gap from 15-VERIFICATION.md:
CR-02 (the session-ended teardown carries no session identity, so a stale consuming task
wipes a newly started session's state on the reentrant coordinator actor) and WR-04
(cancelQueuedWorkItem's update/redownload/repair branch mutates the queue without reaching
the convergence point the whole reconcile design is documented against, stranding a live
session with nothing left to complete it).

Purpose: both defects end in the same SC1-breaking symptom — a session live in the system
while the coordinator believes none exists, or a dead session the coordinator believes is
live — after which progress pushes and completion both bail at the liveness guard, the system
force-expires the card as stalled, and the D-11 expiration policy pauses downloads the user
never touched. Each is reachable from ordinary taps: tap download twice around a drain, or
pause a queued update.

Output: a per-session UUID minted by ensure and threaded through event handling and teardown,
a convergent cancel branch, and a deterministic regression case for each defect. Folded in
from the review set: WR-01's honest liveness-flag doc comment and its post-suspension
ownership re-check in `ensureContinuedSession`, which rides directly on the
`continuedSessionID` this plan introduces.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stale consuming task → coordinator session state | A teardown scheduled by a dead session's stream re-enters the actor and mutates state that may now belong to a successor. |
| system expiration callback → queue state | An uncorrelated system signal can trigger a pause of every schedulable download. |
