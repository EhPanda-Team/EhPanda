<objective>
Close CR-01 and its two enabling warnings by fixing the ownership rule, not the one interleave the
verifier reproduced.

`ensureContinuedSession()` marks a coordinator session live, then suspends inside the client's start
verb. Today a queue drain landing in that window runs `reconcileContinuedSession()`, finds no pending
work, and tears the session down even though `continuedClientSessionID` is still nil. Ownership is
gone while the start is still returning. A second tap then believes no session exists, calls start
again, and the live store — which holds exactly one session and refuses re-entry — returns nil. The
second tap rolls back, the first tap resumes to a failed ownership check and finishes itself, and
the queue is left with running work, no session, and no card until the user taps again.

The invariant this violates is not "the drain branch is wrong". It is: **coordinator ownership may
only be released by a caller that can name the client session it is releasing.** A drain that cannot
name one has not learned that the session is dead — it has arrived early. So it records that
reconciliation is owed and lets the start finish; the start installs the client id and discharges
the debt immediately, re-reading schedulable work at that point.

Round 3 of this phase closed a defect that a green test had concealed, and this is the same shape
again: the held-start regression passes only because `BackgroundProcessingClientSpy` accepts a start
while it already holds a session. A test double more permissive than production cannot gate
production, so the spy is brought onto the live contract in the same plan and the whole suite is
re-run behind it.

Purpose: SC1 and SC2 both rest on one claim — every foreground action that leaves schedulable work
ends with exactly one live session and one card. CR-01 is the last hole in it, and WR-01 is the
reason the hole survived a full round.

Output: an in-flight start that cannot lose its session, an enumerated disposition for every nil
client-id read, a spy bound by the live single-session guard, a leak-safe drain/start/tap regression
stated against the new contract, and coordinator documentation that describes the seam that exists.
</objective>
