<objective>
Close the two client-seam gaps 15-VERIFICATION.md records against SC1 and SC2. The seam's start
verb gains the initial counts, so the store records real numbers before submission and a task
adopted at any moment — including one launched synchronously — reports the queue's real progress
instead of 0 / 0. The seam's progress verb gains the client session id, so a stale actor
continuation that hops onto the main actor after a successor session started is rejected by the
store instead of repainting the successor's card.

Purpose: both defects are invisible to every existing assertion and both are user-visible on a
device. A card whose subtitle reads "120 / 300 pages" while its bar sits at zero is not only
wrong to read — the scheduler reads a task reporting no progress as stalled and expires those
first, which turns a display defect into a lost download.

Design choice recorded: 15-REVIEW.md CR-02 offered two fixes — push the counts immediately after
start, or make the counts part of start. This plan takes the second. The first leaves a real
window (the store still submits with zeros, and a launch that arrives inside that window still
adopts 0 / 0), while the second has no window at all: the counts are recorded on the same
main-actor run that submits. It also keeps `DownloadContinuedSessionTests` honest — that suite's
"no update after start" case is correct behavior under this design rather than an enshrined
defect, and this plan strengthens it to assert the counts the start itself carried.

Output: a seeded, session-identified client seam; a coordinator that presents its recorded client
id on every push and abandons a push it no longer owns; and three deterministic regressions —
two store-side, one coordinator-side through a gated interleave.
</objective>

The delta is real and it is this round's subject: the session used to have one identity (the

- **Primary noun:** the *client session id* returned by `start`. It is the identity every verb that

- **Decision: promote.** This plan finishes the promotion the 15-10 round began — the progress verb

- **Invariant this encodes:** every seam verb that can mutate a live card takes the client session
  id, and the store applies it only when it names the session it holds. A future verb added without
  an id would reopen exactly the defect class CR-01 names.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| coordinator actor → main-actor store | Every push crosses an isolation boundary with no cross-actor FIFO guarantee; a stale continuation can land after a successor session exists. |
| app process → system progress card | The card renders in system UI, outside the app's privacy mask and outside App Switcher snapshot protection. |
| coordinator queue snapshot → system stall detector | The scheduler expires tasks that appear to report no progress, preferring the ones reporting least. |
