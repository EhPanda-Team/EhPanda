<objective>
Close G-15-13 (blocker; the residue of G-15-9, which round 11 closed only for the total-scan
case; violates SC2 and SC3's no-lost-work clause). The 15-30 positive-signal guard covers only a
TOTAL blanking: `scanSucceeded` answers at the directory level, and the all-or-nothing refusal
(`blankedPageCount < manifest.completedPageCount`) disables itself the moment ONE claimed page
survives. One level down, the per-file probe still conflates `file absent` with `file present but
unprobeable`: `pageFileScan` drops a page when `sanitizeAssetFileIfNeeded(at:)` returns false,
and that Bool is false BOTH for a genuinely gone or zero-byte file AND when `attributesOfItem`
throws with the `canReadNonEmptyFile` fallback unable to open the file. A gallery with 100
claimed pages and 99 failed per-file probes yields `99 < 100`: the guard passes, 99 hashes are
destroyed, the manifest is rewritten, `updateDownloadIndex` republishes 1-of-100, and the
D-G7-01 bracket withdraws 99 from the floor — for a movement that never physically happened.
The verification narrowed the reachable trigger: it is NOT descriptor exhaustion or a locked
device (metadata reads need no descriptor and answer under data protection); it is
`attributesOfItem` ITSELF throwing for many-but-not-all files — an I/O error, a permission
change, a volume going away mid-scan — the same reachability class G-15-9 was accepted on, with
an identical, irreversible consequence.

The fix, per the gap's mandated shape (this fix is D-G13-01):

1. **Positive per-file signal.** Extend `PageFileScan` with `unprobedPages: Set<Int>` — claimed
   pages whose file WAS listed by a successful enumeration but whose probe failed. A non-answer
   is never authority to destroy a hash.
2. **Exhaustive classification, not a branch patch.** Replace the probe's Bool decision tree
   with an exhaustive enum classification covering EVERY exit — this is the fifth consecutive
   round in which a fix scoped to the case its regression stages left a sibling open, and the
   sibling here is any probe exit nobody has enumerated. `sanitizeAssetFileIfNeeded` becomes a
   Bool forward so its ~10 probe callers keep byte-identical behavior.
3. **Refuse to blank unprobed pages; keep the second line.** The reconciliation skips any page
   in `unprobedPages`; the failed-scan refusal and the all-or-nothing guard remain behind it.
4. **The wrong premise dies with the fix.** The refusal-site doc currently claims the wholesale
   guard recognises "per-file probe failure en masse" — the exact population it does not cover.
   Rewrite both paragraphs for the three-line shape.

Purpose: a mass partial probe failure can no longer destroy recorded download state, while a
genuine partial loss is still corrected exactly.
Output: the extended scan type, the exhaustive probe classification, the per-file refusal, the
corrected doc, the mass-partial regression watched to fail first, the genuine-partial companion,
and a green full run.
</objective>
