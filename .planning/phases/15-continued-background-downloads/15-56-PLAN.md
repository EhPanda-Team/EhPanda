<objective>
G-15-5's root state: `validateImageData` records its missingFiles verdict only in the in-memory
`validationErrors` dictionary and never reconciles the persisted manifest, whose intact hashes keep
the record claiming complete. The resulting shape — displayStatus `.error` over a complete-claiming
record — satisfies no start gate anywhere (Pause needs `.active/.inactive/.queued`; Retry Failed
Pages needs `.failed` pages, but externally-deleted pages derive `.pending`; Detail's repair needs a
zero completed count that can never hold at validate time), the yellow state dies with the process,
and the badge's hash-claim count diverges from the inspector's live file scan.

The fix is the diagnosis's preferred root fix: make validation's finding durable in the one place
the whole system already trusts — the manifest. On a missingFiles verdict, run the same
positive-signal blanking loop a repair's working-seed preparation runs (D-G5-01,
`reconcileWorkingManifestAgainstPageFiles`), against the gallery's own folder — which for a repair
IS the working folder, so the loop, its guards, its manifest write, its index update and its privacy-
masked log line are all reused rather than rebuilt. When the loop blanks, the record honestly reads
incomplete, and everything downstream is existing machinery: displayStatus falls through to
`.inactive` (the validationErrors entry is cleared — it outranks everything, the hazard the
diagnosis flagged), Resume enables, `resumeMode` resolves `.repair`, the state survives relaunch,
and both count bases converge. When the loop refuses — failed scan, or the wholesale shape its
irreversibility guard exists for — the transient marker stays, exactly as today, and the refusal
family's start affordance is plan 15-57's widened inspector retry.

Purpose: make validation's verdict durable so the record, the badge, the inspector, and the start
gates all read one truth.
Output: the D-G5B-01 durable arm in validateImageData, the promoted blanking loop, rewritten
contract docs, and a piecewise suite that crosses the durable/refusal boundary with relaunch pinned
on both sides.
</objective>

## D-G5B-01 — validation reconciles the record it judged

**On a `.missingFiles` verdict, `validateImageData` re-reads the disk manifest, takes one
`storage.pageFileScan`, and runs `reconcileWorkingManifestAgainstPageFiles` inside
`withdrawingCountedBasisMovement(gid:)`. If the loop blanked at least one hash (the returned
manifest's pages differ), the durable record now speaks and the `validationErrors` entry is cleared.
Otherwise — refusal or a thrown write error — the transient `validationErrors` entry is recorded
exactly as today.**

| Piece | Why |
|-------|-----|
| Fresh scan, not the verdict | `storage.validate` returns on the FIRST failing page; the scan classifies every page. Blanking must cover the missing set, not the reported page. |
| The existing loop, unmodified | Its three refusal lines (failed scan; per-page unprobed holds; all-or-nothing guard) are the licensed evidence rule. A second, laxer blanking path at validate time would be the exact drift D-G5-01's doc warns about. |
| `withdrawingCountedBasisMovement` bracket | The blanking lowers the record's completed count. The bracket is delta-keyed — a refusal withdraws exactly zero by construction — and wrapping makes the write safe even in the mid-session shapes where a live continued session still counts this gallery (a completed-then-validated gallery while the queue is still draining). Same bracket the repair-seed call uses; no new coordination. |
| Clear-on-durable, keep-on-refusal | `validationErrors` outranks `queueStore` and the manifest in `displayStatus`. Cleared, the honest record derives `.inactive` and Resume enables. Kept on refusal, the `.error` surface remains for the family the record cannot speak for — and `canValidateImageData`'s error disjunct keeps Validate re-runnable there. |
| Relaunch honesty | The manifest write plus `updateDownloadIndex` is the durability: a fresh process re-derives `.inactive` and the converged count from disk. No new persisted state is invented. |

**Deliberate residual, dispositioned:** the wholesale shape — every claimed page positively absent —
still refuses, so after relaunch that record reads `.completed` until the user validates again. That
is the irreversibility defence working as designed (the loop cannot distinguish "all 36 deleted"
from a listing shape neither per-page signal explains), it is re-diagnosable in one tap, and its
in-session start affordance lands in 15-57. The refusal-arm test pins the on-disk hashes intact to
keep this boundary honest. Record this residual in the summary so the verifier scores it as a
disposition, not a miss.

**Corrupt-in-place is out of this gap's blanking license, deliberately:** a page whose file exists
but whose bytes mismatch stays on the refusal surface (`.error` + re-runnable Validate; Detail's
destructive redownload is its honest medicine and is 15-57's predicate concern). A presence scan
cannot license destroying the hash of a file that exists, and the G-15-5 truth is about missing
files.
