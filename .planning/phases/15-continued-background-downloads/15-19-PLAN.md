<objective>
Close CR-03: the user's downloaded library is currently written into unified logs as public data.

Download completion logs the gallery title. Enqueue logs the title. Failure, partial failure, pause,
resume, delete and the expiration-interleave notice all publish the gallery identifier, which
resolves to a specific public gallery. Public unified-log fields survive into collected diagnostics
and sysdiagnose archives unredacted, which is precisely the exposure the phase spent a plan avoiding
on the system progress card.

The card was made neutral because it renders outside the app's privacy mask. The log stream is the
same class of surface with a longer memory, so D-09's rule extends here.

There is a second disclosure the review's fix sketch did not reach, and the sweep is scoped to
include it: gallery folders are named `[gid_token] Title` by construction
(`DownloadStore.swift:203-212`, a deliberate Files-app integration decision). Any filesystem error
over a download folder therefore carries the gallery's title inside its own description — and this
module publishes raw error values at public classification in roughly thirty places. The
rejected-response diagnostic additionally publishes a 240-character prefix of the remote page body,
which can contain the title verbatim.

The naming rule the sweep applies, stated once so every site is decided the same way:

> **Operational facts are public; values derived from the user's library are not.** Message text,
> counts, attempt numbers, modes, durations and page indices stay public. Gallery identifiers are
> hash-masked, so correlation across lines survives without disclosure. Titles, paths, remote
> response bodies, and any error value or localized description that can embed them are private.

Most of these lines predate Phase 15. They are in scope by owner decision (D-R4-03), because the
shipping review gate is open now and closing it here is cheaper and more honest than carrying a known
disclosure past the phase that documented it.

Purpose: this is the phase's live security finding, independently confirmed by the verifier and
raised as a Critical by the code review. It blocks shipping regardless of SC1-SC4.

Output: the three named files carrying masked identity and no titles, the module's remaining
error and body-prefix disclosures reclassified, and a permanent scan that fails the build if any of
it comes back.
</objective>

## Trust Boundaries

| Boundary | Description |

| app process → system unified logging | Public fields leave the app's control: they persist in the log store, are readable by anyone who can stream logs from the device, and are collected verbatim into sysdiagnose archives and shared diagnostics. |

| remote response body → log field | A rejected response's prefix is attacker-influenced and gallery-specific, and is currently emitted verbatim at public classification. |
