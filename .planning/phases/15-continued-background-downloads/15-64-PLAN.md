<objective>
Close CR-04 by preserving page-selection intent as a three-state contract from the public retry boundary through payload normalization and pending-page scheduling.

The current `retryPages` accepts out-of-domain indices, delegates update records before validating the caller's explicit selection, and lets `normalizeFetchedPayload` filter invalid repair indices to an empty array before converting emptiness to `nil`. Downstream correctly interprets `nil` as no restriction, so an invalid narrow request can become whole-gallery work. Boundary validation must reject empty/all-invalid input before either repair or update delegation can enqueue, while normalization must independently preserve explicit emptiness so later changes cannot recreate widening.

Purpose: make selected repair fail closed and never broaden the user's requested page set.
Output: current-record validation, lossless selection normalization, and end-to-end regression coverage.
</objective>

## Artifacts this phase produces

- No new production file or public API.
- Revised `retryPages` contract: explicit empty/all-invalid selection returns `.failure(.notFound)` before any state mutation; mixed repair selection carries only current in-range indices.
- Explicit update-mode contract: a request with at least one current in-range page deliberately uses the established whole-update path because update refreshes the gallery as a unit; empty/all-invalid input never delegates to that path.
- Revised `normalizeFetchedPayload` contract: for non-update modes, `nil` remains unrestricted, while any supplied selection remains non-nil even after filtering to an empty set.
- New regression tests in `DownloadRetryPagesTests`, `DownloadRetryUpdateFallbackTests`, and `DownloadZeroPagePayloadTests` covering all three selection states and update-mode mutation ordering.
