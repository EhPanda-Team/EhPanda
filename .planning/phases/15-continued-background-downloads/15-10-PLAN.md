<objective>
Close the SC1 gap from the re-verification (15-VERIFICATION.md, round 2): the coordinator's
completion verb carries no session identity, so a caller that lost ownership across its own
suspension ends whatever session the store currently holds. Under the drain-then-second-tap
interleave the 15-09 bail-out ends the session the second tap legitimately owns — card gone,
request cancelled, system task completed, download running uncovered with no signal (CR-04).
Two sibling paths carry the same missing invariant (`pauseAllSchedulable` per WR-08, the
reconcile drain per WR-09), and the untouched half of WR-01 leaves a refused start
indistinguishable from a created one.

All four are one fix in shape, and this plan is that fix: promote the store's session identity
into the seam's public API — a session handle carrying an id, returned by `start` — and thread
it through both completion sites, the pause loop, and (for symmetry, IN-10) the progress push,
making refusal observable and recoverable. The verification's SC4 caveat explicitly sanctions
this public-API change to the seam; the seam's three verbs, self-finishing stream, and
unimplemented `testValue` all survive it.

**Assumption-delta decision (orchestrator-resolved, recorded):** the identity model is a
*promotion*, not a parallel channel — the session identity the store already effectively has is
surfaced as the handle `start` returns, and the client session id the coordinator stores beside
`continuedSessionID` is the only value `finish` accepts. The coordinator's `continuedSessionID`
remains the coordinator-side identity; no second bookkeeping channel is invented.

**API-coverage checkpoint (orchestrator-resolved, recorded):** no coverage matrix this round —
the external scheduler surface (register/submit/cancel/cancelAllRequests/progress/title/
expiration/setTaskCompleted) is fully integrated and verified by waves 1–8; this plan adds no
external-API capability. The change is the seam's *internal* API: the session handle.

**Spec-less probe fallback (recorded, visible skip):** this phase has no requirement IDs to
probe, so no probe predicates are generated this run; must_haves derive goal-backward from the
15-VERIFICATION.md `missing:` block and SC1.

Output: an identified seam (`BackgroundProcessingSession` handle, `finish(sessionID:success:)`),
a store that no-ops a mismatched completion and returns nil on re-entry refusal, a coordinator
that records the client session id and presents it everywhere it completes / pauses / pushes,
the IN-11 doc-comment correction on the one real suspension window, and two store-level
regression cases. The coordinator-side interleave regressions land in plan 15-11 on top of this
seam.
</objective>
