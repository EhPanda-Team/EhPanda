<objective>
Wire session progress and completion into the queue's existing convergence points, and put the
progress, completion, expiration and unavailability behaviors under automated test.

Purpose: progress reporting is liveness, not decoration — the scheduler forcibly expires tasks
that appear stalled and prioritizes terminating tasks reporting minimal progress, so the push
must ride the per-page flush cadence rather than only firing when the queue mutates. Completion
belongs at the scheduling tail, the single point every queue mutation converges on, so a
session can never outlive its work. Everything the seam decides is unit-testable through the
spy; only the system's grant of the session is not.

Output: two reconcile hooks, one progress push, and the SC1/SC2/SC3 automated coverage the
validation map calls for.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| download queue state → system progress card | Page counts summed from manifests cross into strings rendered outside the app process. |
| system expiration callback → queue state | An uncorrelated system signal mutates every schedulable download's state; the app cannot tell a user cancel from a resource reclaim. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|

| T-15-04 | Denial of Service | summed page counts driving the progress object | low | mitigate | Sums pass through the clamped progress model before the `Int64` conversion; a zero-page gallery yields a total of at least one, asserted in a dedicated case. |

| T-15-11 | Denial of Service | progress starvation causing early expiration | medium | mitigate | The push rides the existing throttled flush, which fires on a page-count branch as well as an elapsed-time branch, so the completed count advances between updates even on slow pages. |
