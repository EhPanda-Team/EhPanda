<objective>
Close G-15-10 (blocker under this project's recorded failure mode: test-double infidelity is how
three consecutive blockers in this phase — G-15-3, G-15-4, G-15-5 — survived their suites).
`BackgroundProcessingClientSpy.start` (`DownloadFeatureTestSupportTypes.swift:264-268`) guards

    guard $0.currentSessionID == nil, !$0.refusesNextStart else {
        $0.refusesNextStart = false
        return true
    }

The guard fires for TWO reasons — the spy's single-session guard and the armed one-shot refusal —
and resets the arm on BOTH. A case that arms a refusal and then races a second start therefore has
its arm consumed by a refusal it did not cause, and every assertion after that point runs against
control state the case believes it still holds. This is the same defect class as the
non-suspending `updateProgress` that let G-15-3 ship green, one layer up: the double's control
surface does not model which event consumes it.

This plan lands FIRST in the round deliberately: plans 15-29 and 15-30 stage new regressions
through this spy, and the standing owner mandate is contract-faithful doubles before the
regressions that lean on them.

Purpose: the spy's refusal arm has exactly one consumer — the refusal it arms — so every present
and future case that mixes refusals with overlapping starts asserts against control state it can
account for.
Output: the split guard, the caller audit recorded in the summary, and one new regression watched
to fail first.
</objective>
