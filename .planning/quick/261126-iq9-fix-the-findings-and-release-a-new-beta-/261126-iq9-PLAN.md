### Settled facts (checked by the planner against the tree; do not re-derive)

1. **Page-address fetch.** `.fetchImageURLs(page)` returns early offline or for a local page, sends
   `.fetchMPVImageURL` once `mpvKey` is known, and otherwise `.fetchThumbnailURLs(page)`, which marks the whole
   preview batch `.loading` (`previewConfig.batchRange(index:)`; the default `.normal(rows: 4)` batch is 40 pages) and
   drops a page whose batch is loading. `.fetchNormalImageURLs` fans out over the batch, and `updateImageURLs` records
   every served URL's file identifier as `.servedURL` sizes. So the three middle sends never duplicate a request, and
   a gallery of 40 pages or fewer (4354007 has 26) already learns its middle sizes from the opening page's batch:
   W-2's fetch adds requests only for a middle batch the opening fetch does not cover.
2. **Ordering.** `.onPresented` is reduced by `lifecycleReducer` first and by `webtoonReducer` last (`mainReducer`'s
   `CombineReducers`), so the merged sends arrive as: `observeDownloads`, `loadLocalPageURLs`, `fetchImageURLs(page)`,
   `prefetchImages`, then the middle pages' `fetchImageURLs`; the opening page's `fetchThumbnailURLs` follows
   (see `ReadingReducerImageFetchTests` for the receive pattern).
3. **The engine runs for the stored history.** Sharing's `appStorage` decodes `[GalleryHistoryEntry]` with a default
   `JSONDecoder`, which calls `GalleryHistoryEntry.init(from:)` per element, so a `SchemaMigrator`-routed `init(from:)`
   migrates every stored element (no blocker). Dates round-trip through `JSONValue` as numbers. `Setting` is the
   precedent: `MigratableModel`, `SchemaV2`, `init(currentFrom:)`, and a `schemaVersion` default equal to the current
   version. That default is load-bearing here: an entry created at version 1 would have a new-rule `false` verdict
   dropped at the next launch.
4. **Engine cost (accepted, reported).** `SchemaMigrator.migrate` round-trips every element through `JSONValue` even at
   the current version: 1,000 entries decode in about 12 ms against about 1.3 ms direct (optimized build on this Mac).
   This plan does not change the engine.
5. **Overlay vs safe-area bars (probed with SwiftUI's ImageRenderer).** An overlay applied after `.safeAreaInset`,
