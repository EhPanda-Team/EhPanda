### Design settled by this plan

- **One ordering.** `waitingQueueGIDs()` (Task 1) is `queueStore.gids` filtered to the galleries whose indexed record
  displays `.queued`. It is the list the scheduler walks (`nextQueuedDownload` reads the same `queueStore.gids`) with
  the non-waiting entries removed, so position 1 is the next to start. Every snapshot gallery's `queuePlace` comes from
  it, the comparator sorts the waiting group by `queuePlace.position`, the badge carries the position for VoiceOver, the
  menu's applicability reads `queuePlace`, and the coordinator re-derives it before every operation. The capture
  fixture (no coordinator) takes the places from the entries' order and documents that.
- **Reorder primitive.** `DownloadQueueStore.reorder(_:)` (Task 2) is a permutation inside the named gids' own slots:
  it never adds or removes an entry, so it is not a queue entrance and the entrance census stays at five; the active
  gallery and any entry that is not a waiting item keep their slots unless named.
- **Mobilizing a paused item** reuses `resume(gid:)` unchanged followed by `ensureContinuedSession()`, exactly the
  `togglePause` resume branch, so the queue-intent bracket's caller list, the entrance census and the "no
  queue-mobilizing entry point takes a block" rule are untouched.
- **The interrupt** (Task 3) takes no scheduling block, deliberately: every failure-persistence handler is gated on
  `shouldSuppressFailurePersistence`, whose `Task.isCancelled` arm stays true in the cancelled run's own task for the
  rest of its life; the page loop already stops on cancellation and skips its forced flush; the interrupted gallery is
  meant to stay schedulable (a block would make a concurrent convergence skip it); and a successor run of the same
  gallery during the wait is the existing overlapping-run disposition (`isSupersededByALiveRun`). So the block census
  (5) and its rule stand and `DownloadSourceInventoryTests` is unchanged. The interrupt cancels the active task, nils
  both halves of the slot, awaits the cancelled run (so its run-exit write-back lands first, as for pause and delete),
  then notifies and converges: ACTIVE-OWNERSHIP CONVERGENCE with no exit in between.
- **Saved pages stay.** A `.redownload` or `.update` run that had already prepared (and so replaced) its working
  folder when it was interrupted would wipe the pages it saved if it restarted under the same mode, so the interrupt
  re-queues it as `.repair`, under the same guards as pause's re-clear: only if its queue-intent generation did not
  move during the wait and it is still queued. "Had prepared" is read from the run's measurement
  (`liveRunProgressBasis(gid:)`), which stands exactly from the preparation's announcement to the run's exit.
- **Interfaces created** (exact):
  - `public struct DownloadQueuePlace: Equatable, Sendable` with `public let position: Int`, `public let waitingCount: Int`,
    `public init(position: Int, waitingCount: Int)`, `public static func places(forWaitingGIDs gids: [String]) -> [String: DownloadQueuePlace]`.
  - `DownloadedGallery.queuePlace: DownloadQueuePlace?` (init parameter `queuePlace: DownloadQueuePlace? = nil`, last).
  - `DownloadBadge.waitingPosition: Int?` (init parameter `waitingPosition: Int? = nil`, last).
  - `public enum DownloadQueueOperation: String, CaseIterable, Sendable` with cases, in this order once Task 3 lands,
    `downloadNow`, `downloadNext`, `moveUp`, `moveDown`, `downloadLast`, and
    `public func isApplicable(status: DownloadDisplayStatus, place: DownloadQueuePlace?) -> Bool`.
  - `DownloadQueueStore.reorder(_ order: [String]) async` (public).
  - `DownloadCoordinator.waitingQueueGIDs() -> [String]` (internal) and
    `DownloadCoordinator.performQueueOperation(gid: String, operation: DownloadQueueOperation) async -> Result<Void, AppError>` (public).
  - `DownloadClient.performQueueOperation: @Sendable (String, DownloadQueueOperation) async throws -> Void`.
  - `DownloadsReducer.Action.performQueueOperation(gid: String, operation: DownloadQueueOperation)` and
    `.performQueueOperationDone(Result<Void, AppError>)`.
