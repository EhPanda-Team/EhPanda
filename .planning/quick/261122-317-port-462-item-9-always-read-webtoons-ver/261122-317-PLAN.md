### Design the planner settled (CONTEXT is authoritative; these fill its open points)

1. **One effective setting, in State.** `ReadingReducer.State.readingSetting` is the user's `setting` with
   `readingDirection` set to `.vertical` while `forcesVerticalReading` (option on and `isWebtoon == true`). It is a
   whole `Setting`, so every helper that already takes a `Setting` (`PageHandler`, `containerDataSource`,
   `imageContainerConfigs`, `landingPage`) reads the effective direction unchanged, and dual pages switch off with it
   (they require a non-vertical direction): a detected gallery cannot half-switch. Writes still go to `setting`. The
   rule itself lives once, `Setting.forcesVerticalReading(galleryIsWebtoon:)`, which the reader and the settings sheet
   both ask, so the reader and the picker lock cannot disagree.
2. **The verdict in State.** `State.isWebtoon: Bool?` is seeded in `State.init` from the history, next to the resume
   page, so a recorded webtoon is built vertical from the first frame (no switch, no toast).
3. **Detection after every action.** `webtoonReducer`, composed last in `mainReducer`'s `CombineReducers`, runs after
   every action: while the option is on and `isWebtoon == nil`, it takes the verdict the known sizes give around the
   committed page (`position.page`). That covers every size source (`recordSize` from MPV lists, served URLs and decoded
   images), every page commit and the option turned on, with no call site to forget; its guard costs a Bool and three
   dictionary lookups. The reading settings write the option straight to the shared setting with no reader action, so
   the view sends `.webtoonReadingPreferenceChanged` when it changes (the pattern `.readingOrientationPreferencesChanged`
   already uses) and the reader decides at once.
4. **The switch reuses the pager machinery.** Nothing in the reducer rebuilds the pager: the view's existing
   `PagerLayout` change (direction, positions), now read from `readingSetting`, sends `.pagerRebuilt`, which places the
   new pager on the page the reader names, as a direction change from the settings sheet already does.
5. **History.** `recordWebtoonVerdict(gid:token:isWebtoon:date:)` and `updateReadingProgress` share one private upsert
   (`updateEntry`), so a gallery with no entry yet gets a front entry (token required), an existing one is updated in
   place, and `recordGalleryOpen` carries the verdict along as it moves the entry. The file's one sanctioned
   `unchecked_subscript_index_access` exception (with its reason and precondition) moves into `updateEntry` unchanged:
   still exactly one, no new suppression. A gallery the history cannot key (non-numeric gid) keeps its verdict for the
   session only, as `flushReadingProgress` does.
6. **Toast only when the direction changes.** The verdict records the reader's effective direction before and after;
   the toast shows only when it changed. A user who already reads vertically, or a "not a webtoon" verdict, sees none.
   The toast is the success style with a title that names the change (a new `AppAlertState.success(title:caption:)`
   factory; the plain "Success" title would not say what happened).
7. **The lock.** `ReadingSettingReducer.State.galleryIsWebtoon` (default false, so the Setting tab never locks) is seeded
   on `.presentReadingSetting` and updated in place (`destination?.modify(\.readingSetting)`) when a verdict lands with
   the sheet open; `locksDirection` combines it with the live option, so turning the option off in the sheet lifts the
   lock at once. The locked picker keeps showing the user's own direction (it is still theirs, D-02); the section's
   footer, shown only while locked, gives the reason and the way out. Page spacing, which applies to the vertical strip,
   is enabled while locked. The toolbar's Dual-Page menu is disabled for a detected gallery, its icon unfilled.
8. **The toggle** sits directly under the direction picker, in the same section, in the Setting tab and the reader's
   sheet alike.
9. **Setting storage** is a private optional `webtoonVerticalReadingPreference` behind the public
   `alwaysReadsWebtoonsVertically`, as `Setting`'s rule for added fields asks ("a field added later must stay optional
   so old blobs keep decoding"); decoded with `decodeIfPresent` in `init(currentFrom:)`.
10. `ReadingFeatureTests` gains a direct dependency on `ReadingSettingFeature` (MemberImportVisibility is on, and the
    tests read the sheet's state).

```swift
        updateEntry(gid: gid, token: token, date: date) { $0.readingProgress = progress }
    }

    /// Records the reader's webtoon verdict for `gid` (D-07) through the same upsert as the reading progress: in
    /// place, leaving the entry's recency, position and resume page untouched, or as a fresh front entry stamped
    /// `date` when the gallery has no history yet. A non-numeric gid, or a new entry with no token, is rejected.

        updateEntry(gid: gid, token: token, date: date) { $0.isWebtoon = isWebtoon }

    /// The upsert behind `updateReadingProgress` and `recordWebtoonVerdict`: applies `update` to `gid`'s entry in
    /// place, or to a fresh front entry stamped `date` when the gallery has no history yet. A non-numeric gid, or a
    /// new entry with no token, is rejected (an in-place update keeps its stored token).
    private mutating func updateEntry(
        gid: String, token: String, date: Date, _ update: (inout GalleryHistoryEntry) -> Void
    ) {
        guard Int(gid) != nil else { return }
        if let index = firstIndex(where: { $0.gid == gid }) {
            // In-place mutation is what keeps the entry's recency and position untouched; `removeAll`
            // + `insert` as in `recordGalleryOpen` would move it to the front. `firstIndex` only ever
            // yields a subscriptable index, restated as a precondition so the exception below stands
            // on a checked invariant rather than on the reader's trust.
            precondition(indices.contains(index), "firstIndex returned an index outside the collection")
            // reason: bounds are precondition-checked immediately above.
            // swiftlint:disable:next unchecked_subscript_index_access
            update(&self[index])
        } else {
            guard !token.isEmpty else { return }
            var entry = GalleryHistoryEntry(gid: gid, token: token, lastOpenDate: date)
            update(&entry)
            insert(entry, at: 0)
        }
    }
```

```swift
// MARK: - Webtoon detection (D-04 to D-07)
extension ReadingReducer {
    /// Decides once whether the open gallery is a webtoon (D-06, D-07). It runs after every action, so the verdict
    /// lands the moment the known sizes allow one, whatever brought them: a size recorded from any source, a newly
    /// committed page, or the option turned on in the reading settings (`webtoonReadingPreferenceChanged`). With the
    /// option off, or with a verdict already recorded, it does nothing.
    var webtoonReducer: some ReducerOf<Self> {
        Reduce { state, _ in
            guard state.setting.alwaysReadsWebtoonsVertically, state.isWebtoon == nil,
                  let isWebtoon = state.webtoonVerdictFromKnownSizes
            else { return .none }
            record(isWebtoon: isWebtoon, in: &state)
            return .none
        }
    }

    /// Records the verdict for the session and in the browsing history, through the same upsert as the reading
    /// progress (D-07), so the gallery is checked only once. A gallery the history cannot key keeps its verdict for
    /// the session.
    private func record(isWebtoon: Bool, in state: inout State) {
        state.isWebtoon = isWebtoon
        let gid = state.gallery.id
        let token = state.gallery.token
        guard gid.isValidGID else { return }
        @Shared(.galleryHistory) var galleryHistory
        $galleryHistory.withLock {
            $0.recordWebtoonVerdict(gid: gid, token: token, isWebtoon: isWebtoon, date: date.now)
        }
    }
}

extension ReadingReducer.State {
    /// The height-to-width ratio from which a page is extremely tall (D-05): a phone screenshot is about 2.17 and a
    /// manga page about 1.4.
    static let webtoonAspectRatio = 2.5

    /// The three pages a verdict is drawn from (D-04): the page before `page`, `page` and the page after it, moved
    /// inside the gallery on its first and last page. `nil` for a gallery of fewer than three pages, which is never
    /// detected.
    static func webtoonSamplePages(around page: Int, pageCount: Int) -> ClosedRange<Int>? {
        guard pageCount >= 3 else { return nil }
        let first = min(max(page - 1, 1), pageCount - 2)
        return first...(first + 2)
    }

    /// The verdict the known sizes give around the committed page (D-05, D-06): a webtoon when the three sampled
    /// pages are all extremely tall, not one when any of them is not, and `nil` while a sampled page's size is not
    /// known yet. The sizes are the reader's own (`pageSizes`), from whichever source gave them.
    var webtoonVerdictFromKnownSizes: Bool? {
        guard let pages = Self.webtoonSamplePages(around: position.page, pageCount: gallery.pageCount) else {
            return nil
        }
        let sizes = pages.compactMap({ pageSizes[$0]?.pixelSize })
        guard sizes.count == pages.count else { return nil }
        return sizes.allSatisfy({ Double($0.height) / Double($0.width) >= Self.webtoonAspectRatio })
    }
}
```
