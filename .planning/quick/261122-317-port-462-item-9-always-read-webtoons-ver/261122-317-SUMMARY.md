# Phase 261122-317 Plan 01: Always Read Webtoons Vertically Summary

There is now a reading option, "Always Read Webtoons Vertically", off by default. While it is on, the reader checks each gallery once. It looks at the page sizes it already knows for three pages around the current page, and calls the gallery a webtoon when all three have height / width >= 2.5. The verdict is stored as `GalleryHistoryEntry.isWebtoon`, written through the same upsert as the reading progress. A webtoon is then read vertically through the reducer-level `readingSetting`; the user's own `readingDirection` is never written. A switch in mid-session shows a titled success toast. The reader's settings lock the direction picker and add a footer explaining why, and the toolbar's Dual-Page menu is disabled for a detected gallery.

`actuals.tokens` is chars/4 over `git diff b4a1bbe2c..HEAD`: 20 files, 913 insertions, 37 deletions.

## Open for the owner (the planner's choices beyond CONTEXT)

1. One effective setting in State: `readingSetting` is the user's `setting` with `readingDirection = .vertical` while `forcesVerticalReading`. The rule lives once, in `Setting.forcesVerticalReading(galleryIsWebtoon:)`, which both the reader and the settings sheet ask.
2. The verdict is held in `State.isWebtoon`, seeded from the history in `State.init` next to the resume page. A recorded webtoon is therefore built vertical from the first frame, with no switch and no toast.
3. Detection runs after every action (`webtoonReducer`, composed last). The view sends `.webtoonReadingPreferenceChanged` when the option changes, so turning the option on decides at once.
4. The switch reuses the existing pager rebuild: the `PagerLayout` change, now read from `readingSetting`, sends `.pagerRebuilt`.
5. History:
   - `recordWebtoonVerdict` and `updateReadingProgress` share one private upsert (`updateEntry`).
   - The one subscript-lint exception moved into that shared upsert unchanged; it is still the only one in the file.
   - A gallery with a non-numeric gid keeps its verdict for the session only.
6. The toast shows only when the reader's direction actually changes. It is a new titled `AppAlertState.success(title:caption:)` factory.
7. The locked picker still shows the user's own direction. Its footer appears only while it is locked, and page spacing stays enabled while locked.
8. The whole Dual-Page menu in the toolbar is disabled for a detected gallery, and its icon is unfilled.
9. The toggle sits directly under the direction picker, in both the Setting tab and the reader's sheet.
10. The option is stored as a private optional `webtoonVerticalReadingPreference`, decoded with `decodeIfPresent`, and ReadingFeatureTests gains a direct dependency on ReadingSettingFeature.

Also from the orchestrator (CONTEXT):
- Verdicts are recorded only while the option is on, and they are kept when it is turned off.
- A gallery with fewer than three pages is never detected.
- The Setting tab never locks the picker.
- Tag detection was not taken over from dyphire's reference.
