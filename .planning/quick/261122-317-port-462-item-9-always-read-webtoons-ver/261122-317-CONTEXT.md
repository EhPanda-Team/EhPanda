## Owner decisions (2026-11-22, locked)

- **D-01 One option.** A new reading setting, "Always read webtoons vertically" (working English label; each
  locale writes its own native label). It is the only switch: turning it on turns detection on. There is no
  separate "detect webtoons" option. Default off.
- **D-02 Effect.** With the option on and the open gallery detected as a webtoon, the reader reads that gallery
  vertically, for that gallery only. The user's own reading direction (`Setting.readingDirection`) is not written.
- **D-03 Locked picker with a reason.** With the option on and the open gallery detected, the direction picker in
  the reading settings is disabled and the UI says why (a footer). Turning the option off is how a user undoes it.
- **D-04 Sampling.** Three pages around the current page `c`: `c-1, c, c+1`; on the first page `c, c+1, c+2`; on
  the last page `c-2, c-1, c`.
- **D-05 Threshold.** A page is extremely tall when height / width >= 2.5 (a phone screenshot is about 2.17, a
  manga page about 1.4). A gallery is a webtoon when all three sampled pages are extremely tall.
- **D-06 Wait for sizes, then switch with a toast.** Sizes come only from the reader's existing known-size
  machinery (`KnownPageSize` / `State.pageSizes`, any source: MPV original sizes, the served URL's file identifier,
  the decoded image); no new size source. When the three sizes are not known yet, the reader opens in the user's
  direction and decides as soon as they are. If it decides "webtoon" mid-session, it switches to vertical and shows
  a toast (the reader's in-app `toast`, `AppAlertState`; not a system notification). A gallery whose verdict is
  already recorded opens in its direction at once, with no toast.
- **D-07 Detected once, persisted in the browsing history.** The verdict (webtoon or not) is recorded per gallery
  id so a gallery is detected only once. It is stored as one optional field on `GalleryHistoryEntry` (nil = not
  checked yet), written through the same upsert path as the reading progress: same cap, same prune, absent-tolerant
  decode, no schema migration. Clearing the history makes a gallery be checked again (accepted). The owner chose
  this over a separate list or session-only state as the cleanest approach.

## Orchestrator decisions (to report to the owner afterwards)

- Detection runs and verdicts are recorded only while the option is on. Turning it off keeps recorded verdicts;
  turning it back on reuses them.
- A gallery with fewer than three pages is never detected (no verdict is recorded).
- The effective direction is reducer-level state the view reads; it takes precedence over the automatic layout
  ("match screen orientation"), which keeps writing the user's setting as today.
- Everything in the reader that reads the direction (pager vs. strip, dual pages, page spacing picker enablement,
  gesture and accessibility stepping, page mapping) reads the effective direction, so a detected gallery never
  half-switches. The reader toolbar's two-page toggle, which also selects a horizontal direction, is disabled for
  a detected gallery the same way as the picker.
- In the Setting tab (no gallery open) the picker is never locked.
- dyphire's reference (`93e767147` on `pr-462`) detects by tag and derives an `effectiveSetting` in the view; the
  tag detection is not taken. The port still credits dyphire with `Co-authored-by: dyphire <qimoge@gmail.com>`, as
  every other item of this port does.
