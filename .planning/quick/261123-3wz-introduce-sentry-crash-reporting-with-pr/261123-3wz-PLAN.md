<objective>
Add Sentry crash reporting to EhPanda with the privacy-preserving settings of the established pattern in
CONTEXT.md: crashes only, nothing about the person, a beforeSend scrubber that never drops an event, the SDK
started at launch regardless of the analytics choice (D-01), the DSN carried only by release archives from a
repository secret and read through AppInfo (D-02), a privacy-manifest entry, and a CI dSYM upload. README files,
the privacy policy and any settings UI stay out of scope (D-03).

Purpose: release crashes become diagnosable without collecting anything about the person using the app.

Output: the CrashReporting module (scrubber, options, start rule) and its tests, the launch call, the DSN
plumbing, the privacy-manifest entry, actions-tool/upload-dsyms.sh with its tests, and the three release
workflows wired and tested.

Ordering (recorded on purpose; the structure is the established pattern, so no exploratory tracer is needed):
Task 1 lands the scrubber before anything can start the SDK, so no commit ever starts the SDK unscrubbed.
Task 2 is the end-to-end slice (build setting, Info.plist, AppInfo, launch call, SDK start) and proves it with
Release simulator launches with and without a DSN. Task 3 is the CI slice. One commit per task.

Discretion choices made here (CONTEXT "Claude's Discretion"), for the owner to veto at plan review:
- Module CrashReporting, public type CrashReporter (a type must not share its module's name), SDK pinned
  exactly at 9.35.0 (the newest 9.x, checked 2026-11-23) so that a new SDK option can only arrive through a
  reviewed bump.
- Sentry environment = DistributionChannel.current.rawValue (github, altstore, sidestore, altstorePAL, beta,
  source).
- Start rule = never in a Debug build, never when XCTest hosts the process, never without a DSN. EhPanda's
  UI-test, hosted visual test, capture and launch-automation facilities exist only in Debug builds (the scheme's
  Test action builds Debug and their resolvers compile to nothing in Release), so the Debug refusal is what
  excludes every automation launch. The module must not read their environment keys, because the Release
  isolation scan (Scripts/visual/verify-release.py) forbids that text in a Release binary.
- EhPanda redaction additions: scheme-less E-Hentai and ExHentai host references, and the three credential
  cookies of Defaults.Cookie (ipb_member_id, ipb_pass_hash, igneous) as name=value pairs. Bare gallery IDs and
  tokens are not pattern-matched: they cannot be told apart from the hashes and addresses a crash report
  legitimately carries.
- No xcconfig default and no local override for the DSN: xcconfig parsing treats `//` as a comment and would
  cut a DSN at `https:`, and no local build needs one, because the start rule refuses every Debug build.
- The workflows keep each run's dSYMs as an artifact, so the --reupload form has a dSYMs folder to work on after
  a failed CI upload.
- Nine additional 9.35.0 options are set off, following the pattern's rule that every switch that could record
  more than the crash is set explicitly (listed in Task 2).

`if [[ "${BASH_SOURCE[0]}" == "$0" ]]; then main "$@"; fi`, so the tests can source it. `main` sets the shell
options and an ERR trap that sends any unexpected failure through the same single `fail` function. That keeps
the CI form unable to exit non-zero.
Steps: (1) parse the form; (2) check the four variables and that the dSYMs folder exists and holds at least one
`*.dSYM` entry; (3) pick the asset from `uname -m` (arm64 or x86_64; anything else fails); (4) create a
`mktemp -d` work directory, removed on exit; (5) download with curl (`--fail --silent --show-error --location
--proto '=https' --tlsv1.2`, output to a file in the work directory) from
`https://github.com/getsentry/sentry-cli/releases/download/<version>/sentry-cli-Darwin-<arch>`; (6) compare
`shasum -a 256` of the file to the pinned value and fail on a mismatch before the file is ever made executable
or run; (7) print `sentry-cli <version> (<asset>) matches its pinned SHA-256.`; (8) chmod it and run
`<cli> --url "$SENTRY_URL" debug-files upload --org "$SENTRY_ORGANIZATION" --project "$SENTRY_PROJECT" --type dsym <dSYMs folder>`
(`--url` must come before the subcommand; never upload sources), with stdout and stderr piped through
`hide_token`, and take sentry-cli's own exit status through PIPESTATUS.
`hide_token` reads stdin line by line (keeping a last line that has no newline) and replaces every occurrence
of the token's value with `[hidden]` using bash parameter expansion, so the token never becomes the argument
of a subprocess. An empty token passes the text through unchanged.
The token is never passed as a command-line flag, never printed, never echoed into the warning or error line.
The script never pipes a download into a shell, never evaluates downloaded text and never turns on shell
tracing. It must pass `shellcheck` with no findings at any level.
