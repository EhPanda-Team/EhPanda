## What each port does, and how it differs from #462

1. **Favorites sort order** (`c2d40437`, sort-order hunks only). `parseFavoritesSortOrder` reads the selected option of
   `div.searchnav select[onchange*=inline_set=fs_]` (`p` is `.lastUpdateTime`, `f` is `.favoritedTime`, else nil); same
   mapping as #462. `fetchGalleriesDone` and `fetchMoreGalleriesDone` keep the current order when a page has none.
   *Not taken:* #462's third hunk, which sets `state.sortOrder` from the requested order in `fetchGalleries`.
   develop's `selectSortOrder` flow is deliberately server-confirmed (a failed fetch keeps the old mark,
   `SortSelectionTests`), so an optimistic write would undo it.
   *Also changed:* the stub page in `GalleryRequestBaselineTests` still had the dead "Use Posted" link; it now has the
   real select. Its assertion (`.favoritedTime`) is unchanged.
2. **Cache caps** (`37d76aca`). `DataCache.Configuration` default `diskSizeLimit` 0 to 2 GiB
   (`defaultDiskSizeLimit`; the existing sweep trims to half, checked every 256 MiB written). `initializeWebImage` sets
   Kingfisher `diskStorage.config.sizeLimit` and SDWebImage `config.maxDiskSize` to 1 GiB.
   *Difference:* #462 set only Kingfisher; SDWebImage is added because the owner and the review ask for it.
   `AppFeatureTests` gets the SDWebImage product in `Package.swift` (not the pbxproj) to read the limit back.
3. **Tag prefixes** (`9f787e8c`). `analyze` strips leading `~`/`-` for matching; `autoComplete` re-adds it.
   *Difference:* the search menu's `.searchCompletion` keeps the prefix too (#462 did not touch it, and the menu would have
   turned an exclusion into a plain term). The menu path is not covered by a test and not checked on a device.
4. **About**: `code_contributor.dyphire` and `_link` (`https://github.com/dyphire`) in `Constant.xcstrings`, every locale
   filled, `shouldTranslate: false`, as Kaed3mi's; listed after Kaed3Mi in `AboutView`. No new copy.
