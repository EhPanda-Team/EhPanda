## Planner decisions (owned here — reasoning stated; execute as written, do not re-litigate)

**PD-1 (DEF-15-06) Fix the interface, not the two call sites.** Both live implementations are pure actor-state reads that cannot fail: `DownloadCoordinator.fetchDownloads()` is `async -> [DownloadedGallery]` returning `indexedDownloads()` (`DownloadClient+PublicAPI.swift:19`), `fetchFolders()` is `async -> [String]` returning `userFolders` (`DownloadClient+Folders.swift:10`). The `throws` on the two `DownloadClient` closures is vestigial (it dates from the module extraction, `ecfd389b`), no test double anywhere throws from either (all 40 doubles are `{ [] }`, `{ [download] }`, `{ folders() }` or counters), and FOUR call sites — not the two the item names — `try await` them inside `.run` with no `catch:` (`DownloadsReducer.swift:260, 296`; `DetailReducer+Download.swift:73`; `FolderManagerReducer.swift:189`). Adding `catch:` arms would add dispositions for failures that cannot happen (a `.failed` list state and a "deliberately silent" folder-fetch failure), leave the other two sites inconsistent, and keep the false contract. So: drop `throws` from both closures, add the `= { [] }` default `@DependencyClient` requires for a non-throwing, non-optional return (same style as `observeDownloads`' default on the line above; the unimplemented endpoint then `reportIssue`s and returns `[]`, exactly as `fetchDownload`'s optional does today), and drop `try` at all four sites — the compiler flags every one (`no calls to throwing functions occur within 'try'` is a warning, and the build gate is warning-free). Consequence, deliberate: `DownloadsView.downloadsList`'s `case .failed(let error) where store.downloads.isEmpty: ErrorView(error:action: fetchDownloads)` becomes unreachable (nothing sets `.failed` on this state — grep confirms `loadingState` is written only at `DownloadsReducer.swift:258, 271`) and is REMOVED rather than left reading as a live retry surface; the `switch` keeps its `.loading where empty → LoadingView` case and `default → List`. `LoadingState` stays the type of `loadingState` (shared enum; a Bool rename would be churn) with a one-sentence doc on the property saying only `.loading`/`.idle` occur and why. If the reads ever gain a real failure mode, the signature change back to `throws` makes the compiler enumerate every site — the property this fix buys.

**PD-5 (DEF-15-09) One shared fence helper, both detectors rewritten, deadline gone at those two sites only.** Add to `DownloadFeatureTestHelpers.swift` (protocol extension of `DownloadFeatureTestCase`, beside `waitForTaskValue`) a helper such as `func collectSnapshots(from stream: AsyncStream<[DownloadedGallery]>, untilFence fenceGID: String) -> Task<[[DownloadedGallery]], Never>` whose task appends every snapshot until one whose `map(\.gid) == [fenceGID]` and then returns what came before it. Doc on it (this is the single owner of the reasoning; both call sites refer to it): why a fence and not a clock — `DownloadObserverHub.observe` registers the continuation before returning and the stream is `AsyncStream.makeStream` (unbounded buffer), and every convergence exit awaits `notifyObservers()` before returning, so when the operation returns the notification is either buffered ahead of anything pushed afterwards or will never come; wall time cannot tell "never" from "not yet scheduled" (15-21 recorded 13.2 s at one of these sites), a fence can, and the pre-fix bug fails at once with a name. Also: no deadline on `await task.value` — the test itself pushes the fence into a registered continuation, so termination is by construction; and do not rely on cancellation draining the buffer. In each detector: build the fence with `sampleDownload(gid: "fence-\(UUID().uuidString)", title: "Fence", status: .completed)`, create the collector BEFORE the mutation (as now), run the operation, then `await fixture.manager.observerHub.notify([fence])` (`notify` dedups against the last observed snapshot; a fresh gid always passes), then `let emissions = await observerTask.value`; drop the `defer { observerTask.cancel() }` and the `waitForTaskValue` call. Assertions become sequence pins that hold regardless of how many further convergence emissions land before the fence (the delete test's scheduling tail spawns a `finishActiveTaskIfOwned` notify asynchronously, so an exact count would be a coin flip — the production guarantee is "at least one converged emission, first"): delete test — `emissions.count >= 2`, `emissions[0].map(\.gid) == [first, second]`, `emissions[1].map(\.gid) == [second]`, `emissions.dropFirst().allSatisfy({ $0.map(\.gid) == [second] })`; ownership test — `emissions.count >= 2`, `emissions[0].map(\.gid) == [first, second]`, `emissions[1].map(\.gid) == [first, second]` (the failed removal retains the record). Replace the two long IN-01 comment blocks with a short pointer to the helper's doc plus one sentence: the ten-second bound that stood here (15-64/15-74) is retired at these two sites because the fence measures the fact the clock could not; `waitForTaskValue` and its doc are untouched (13 other callers keep it).
