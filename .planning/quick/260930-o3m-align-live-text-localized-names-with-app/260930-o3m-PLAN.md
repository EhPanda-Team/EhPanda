<reader_launch_procedure>
This procedure opens the reader hermetically in a chosen language. It reuses the existing UI-test seam: `DeepLinkLauncher.configureStubbedLaunch` sets `EHPANDA_UITEST_STUB_NETWORK=1` and `EHPANDA_UITEST_FIXTURE_DIR`, and the DEBUG `UITestStubURLProtocol` then serves `GallerySinglePage.html`, `GalleryDetail.html` and `FrontPageList.html` from that directory. The procedure opens `UITestConstants.singlePageURL(scheme: "ehpanda")`. Every page renders the reader's failure placeholder, because fixture images never load. The procedure drives the simulator only with `xcrun simctl` and `sim-use`.

Variables:
- `U` = the simulator UDID. `DEV` = `iphone` or `ipad`.
- `PRODUCTS` = the first `BUILT_PRODUCTS_DIR = ` value printed by `xcodebuild -showBuildSettings -project EhPanda.xcodeproj -scheme EhPanda -destination 'generic/platform=iOS Simulator'`.
- `APP="$PRODUCTS/EhPanda.app"`.
- `BUNDLE_ID` = the output of `/usr/libexec/PlistBuddy -c 'Print :CFBundleIdentifier' "$APP/Info.plist"`.
- `PAGE_URL='ehpanda://e-hentai.org/s/0000000000/3103480-2'`. This is primaryGID 3103480, singlePageToken 0000000000, pageIndex 2.
- `EVIDENCE="$SCRATCH/o3m/evidence"` (session scratch, outside the repository; export `SCRATCH` in every call).
- Portrait centre in native points: iPhone Air `(210, 456)`, iPad mini 6 `(372, 566)`. The screen centre is the same physical point in every orientation, and `sim-use tap -x/-y` always uses device-native portrait space, so these coordinates are correct in landscape too.

Locale arguments and expected names:

| Locale | Launch arguments | Expected name |
|---|---|---|
| de | `-AppleLanguages '(de)' -AppleLocale de_DE` | `Live-Text` |
| ja | `-AppleLanguages '(ja)' -AppleLocale ja_JP` | `テキスト認識表示` |
| zh-Hant | `-AppleLanguages '(zh-Hant)' -AppleLocale zh_TW` | `原況文字` |
| en | `-AppleLanguages '(en)' -AppleLocale en_US` | (used only for the reading-direction set and restore steps) |

Steps:
- **P1 Install.** Run `xcrun simctl install "$U" "$APP"`.
- **P2 Fixtures.**
  - Set `DATA=$(xcrun simctl get_app_container "$U" "$BUNDLE_ID" data)` and `FIX="$DATA/Library/o3m-uitest-fixtures"`, then run `mkdir -p "$FIX" && cp EhPandaUITests/Fixtures/*.html "$FIX/"`.
  - A copy inside the app's own data container is guaranteed readable. It lives under `Library/`, away from the user-owned downloads area, so it cannot be mistaken for a gallery folder.
  - Re-run P2 after every xcodebuild run that reinstalls the app. It is idempotent.
- **P3 Launch.** Run `SIMCTL_CHILD_EHPANDA_UITEST_STUB_NETWORK=1 SIMCTL_CHILD_EHPANDA_UITEST_FIXTURE_DIR="$FIX" xcrun simctl launch --terminate-running-process "$U" "$BUNDLE_ID" <locale launch arguments>`.
- **P4 Foreground.**
  - Poll `sim-use ui --device "$U" --json --no-raw` up to 15 times, with no `sleep` because each call takes about 1 s, until `.data.appPackage` equals `$BUNDLE_ID`.
  - A system alert may cover the app. Handle it only as execution rule 6 allows; otherwise, STOP.
- **P5 Deep link.** Run `xcrun simctl openurl "$U" "$PAGE_URL"`. This is warm delivery, the same route as `DeepLinkLauncher.openWarm`.
- **P6 Panel.** Poll `sim-use ui --device "$U" --json` up to 10 times, keeping the raw tree. The reader is ready when the output contains the identifier `reading_page_indicator`. The toolbar is visible only while the panel is shown.
  - If the raw tree shows `reading_view` but no indicator, tap the centre once with `sim-use tap --device "$U" -x <cx> -y <cy>`. This mirrors `ReaderPageProbe.showPanel`.
  - If 10 polls pass without either identifier, also tap the centre once.
  - Then poll up to 5 more times for `reading_page_indicator`.
- **P7 Fallback (only if P6 fails).**
  - Repeat P3 with `SIMCTL_CHILD_EHPANDA_AUTOMATION_GALLERY_URL="$PAGE_URL"` added. This is the DEBUG `AppLaunchAutomation` seam: `AppReducer.runLaunchAutomation` sends `handleDeepLink`.
  - Skip P5, then repeat P4 and P6.
  - If the indicator still does not appear, STOP and report.

Captures (`NAME` = `$DEV-<portrait|landscape>-<large|ax5>-<de|ja|zh-Hant>`):
- **C1 Bar.**
  - Run `sim-use ui --device "$U" --json --no-raw > "$EVIDENCE/$NAME-bar.json"` and `sim-use screenshot --device "$U" --output "$EVIDENCE/$NAME-bar.png"`, then `sips -Z 1400 "$EVIDENCE/$NAME-bar.png" >/dev/null`.
  - The Live Text control is **in the bar** if the JSON has an entry with `role` `Button` whose `label` exactly equals the expected name.
- **C2 Overflow (only if C1 did not find the control in the bar).**
  - Run `sim-use tap --device "$U" --id OverflowBarButtonItem`, then save `$NAME-overflow.json` and `$NAME-overflow.png` the same way as C1, including the downscale.
  - The control is **in the overflow** if an entry label exactly equals the expected name.
  - If it is in neither place, STOP.
- **C3 Large Content Viewer (portrait `ax5` only, when the control is in the bar).**
  - Let `(cx, cy)` be the centre of the Live Text entry's frame: `x + width/2`, `y + height/2`. In portrait, UI space equals native space.
  - Run `sim-use touch --device "$U" -x <cx> -y <cy> --down`.
  - Then run `sim-use ui --device "$U" --json --no-raw > "$EVIDENCE/$NAME-lcv.json"`. This also gives the HUD time to appear.
  - Then run `sim-use screenshot --device "$U" --output "$EVIDENCE/$NAME-lcv.png"` and view it. If no HUD is visible, take up to 2 more screenshots, overwriting the file, while still holding.
  - Finally, run `sim-use touch --device "$U" -x <cx> -y <cy> --up` and downscale the PNG with `sips -Z 1400`.
  - Releasing over the item toggles Live Text. This is expected: the state is local to the reader and resets on the next launch.
