## What changed

**Task 1 — the retirement.**
`completeDownload(gid:download:)` now logs and settles, nothing more: the `completedFolderURL`
computation, the sweep call and `removeSupersededFolders(gid:token:keeping:)` are gone, and the
private `ProcessDownloadResult` that existed solely to carry the folder path to the sweep went with
them (`fetchNormalizeAndDownload` returns `Void`). `removeGalleryFolders(gid:token:)` lost its
`keeping:` parameter and its path comparison, and carries the invariant on its declaration: it
removes EVERY folder of one gallery — by `[gid_token]` prefix or by manifest identity, including one
the user renamed or copied in Files — and is therefore reserved for `delete(gid:)`, its only caller
(`DownloadClient+PublicAPI.swift:241`).

The repair-seed machinery is gone in full: `RepairSeedContext`, `repairSeed(for:payload:)`,
`RepairSeed`, `DownloadStore.materializeRepairSeed(from:manifest:to:)` and the then-stranded
`linkOrCopyReadableAsset(at:to:)`, plus its localized error string (`downloadStoreAssetUnreadable` /
`download_store.asset_unreadable`, deleted from all six locales). `setupWorkingFolder` is now
`(folderURL:shouldReuse:) throws -> Void` — wipe if not reused, then ensure the directory exists —
and carries the other half of the invariant: a run prepares and works only in its own working folder,
and the wipe is the caller's `shouldReuseWorkingFolder` verdict, i.e. the user's own start mode.

With no carry left, `prepareWorkingSeed` hands `authorizedReconciliationScan` the destination scan
as-is (the `PageFileScan` rebuild at the old `:451-466` is deleted, and the function's fourth
parameter `carriedUnprobedPages:` with it), and `authorizedReconciliationScan` answers with `rescan`
directly instead of rebuilding a scan around it. `existingDownload:` is dropped from
`prepareWorkingSeed`, `prepareWorkingSeedAnnouncingProgress` and the `#if DEBUG` shim;
`performDownload` keeps its own `existingDownload` for the execution context.

**Task 2 — the pin.** `DownloadProcessTests.testAFullRunLeavesAnotherFolderOfTheSameGalleryUntouched`
stages the record's folder exactly as the stale-selection case does, copies it whole into a second
user folder (`Copies/<gid> - Pause Race`, no `[gid_token]` prefix, so it matches by manifest identity
alone), runs the full `processDownload`, then asserts: `.completed` in the record's own folder, and
the other folder still present with an identical sorted listing and an identical manifest, with
`galleryFolderURLs` returning exactly the two. Which folder the record points at is read rather than
presumed, since `deduplicatedDownloadIndex` arbitrates by modification date and the property is
symmetric. `verifyCompletedProcess`'s assertions are unchanged; only its comment was reworded, since
there is no sweep to find nothing to remove.

**Task 3 — the record.** G-15-2H carries a `resolution_2026_08_19` note with the decision, the
iPad-multitasking why, the accepted two-folder consequence, the retained Code=4 fingerprint, and the
pins with both commit hashes.
